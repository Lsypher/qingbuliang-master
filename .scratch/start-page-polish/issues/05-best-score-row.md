# 05: 最高分行（奖杯 + 专用文案 + 居中排布）

**What to build:** 最高分从一行裸文字变成"小奖杯图标 + 最高分：N"的一行，数字位数从 1 位变到多位时整行始终水平居中；开始页使用带全角冒号的专用文案，**结算页那行文案保持原样不受影响**。

**Blocked by:** 03（两者共用同一个纯函数模块与测试文件，须在其后扩展）

**Status:** done

- [x] 这一行的结构为：行容器 → 奖杯图标（44×44）+ 间距 10 + 文字；整行（图标宽 + 间距 + 文字宽）相对容器中心左右对称
- [x] 数字为 1 位与 3 位时整行都居中（不出现"位数一变就偏"）
- [x] 奖杯图片缺失或未交付时不显示破图：该行只显示文字且仍然居中
- [x] 开始页显示带**全角冒号**的专用文案；结算页那行仍是原来那句，文案表里两条并存且各自有注释说明用途

### 备注

- **"图缺失"那条路径在编辑器里就是真实路径**：编辑态取不到 resources bundle（03 票已证），所以 `showBestScoreIcon()` 在编辑器走的正是"加载失败 → 收起奖杯 → 整行只剩文字且居中"，上表前两行就是它的实测。奖杯**显示**的路径只有运行时走得到：本次没有留图（本机编辑器窗口抓不到游戏画面，与 03 / 04 同一限制；截图证据按 spec 归 **07 号票**）。
- **交付的奖杯图与规格有出入**（实测，供 07 / 美术复核）：文件是 2048×2048 的方画布，但奖杯本体只占 (328,456)–(1712,1640)，即画布宽的约 68%、高的约 58%（约 1385×1185 像素）；导入后的 SpriteFrame 的 `rect` 与 `originalSize` 都是整张 2048×2048（未裁剪）。因此按规格的 **44×44 节点渲染时，奖杯本体约 30×26 像素**，不是满 44。本票**不做程序侧补偿**——把节点放大到 65×76 之类会让"图标 44×44 + 间距 10"这条版面约定失真，建议美术按规格重出（88×88、奖杯填满画布），同名覆盖即生效。
- 奖杯节点 `trim = false`：与标题艺术字同一套导入约定（保留原始画布、不裁剪）；对这张图而言 `trim` 开与不开结果相同（`rect` 就是整张画布），这条设置只是把约定写在明面上。
- `updateRenderData(true)` 是引擎的**内部 API**（未进官方文档），已在该行注释里点明"升引擎时要复核它是否还在、还同步"。
