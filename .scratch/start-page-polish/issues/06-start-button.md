### 九宫格边距为什么是 843 / 328（这次最容易静默出错的一处）

引擎（`cocos/2d/assembler/sprite/sliced.ts`）把 `SpriteFrame` 的 border **同时**当两样用：纹理里的切分位置（**原图像素**）与角块画出来的大小（**设计像素**），两者共用一个数。由此有两条硬约束：

1. **`left ÷ top` 必须等于 `360 ÷ 140`**：角块画出来的宽 = `节点宽 ÷ (left + right)`、高 = `节点高 ÷ (top + bottom)`，只有这个比例能让两个方向**同倍缩放**——否则四角装饰在两个方向上被不等倍拉伸（圆头变扁）。
2. **`left ≤ 180`、`top ≤ 70`** 才有"中段"。交付图实测：画布 2400×800、不透明区 2288×656（半高 328）、左右两端的圆头半径约 328px（占满半个画布）——角块必须覆盖整个圆头，`left` 就下不来，于是两倍角块（1686px）放不下 360 宽的按钮，引擎按比例缩角块、中段被挤成 0。

所以取 **`left = 843 ≈ 328 × 360 ÷ 140`、`top = 328`**：满足①，四角同倍缩放、不变形（不满足②的代价是按钮由四块角块拼成、丢掉画面正中的高光，这条已写进出图需求文档，重出图即可拿回中段）。

**验证方式**：按 `sliced.ts` 的算式写了个一次性脚本（已删），把三种边距在 360×140 下的渲染结果算出来对比——`843 / 328` 得到一块端头圆润、装饰完整的木牌；`336 / 328`（角块贴合装饰但不等比）是端头被横向拉扁的怪形；文档原来那组 `140 / 120` 明显切坏了圆头。选定后核对引擎资源：两张图的 `capInsets` 已是 `[843, 328, 843, 328]`、`packable = false`、`rect` 为整张原始画布。

### 备注

- **"按下缩小"没有用引擎的缩放过渡**：`Button.Transition` 一次只能选一种，换图已经占了 `SPRITE`，所以 0.95 那条自己接在触摸事件上（缩按钮节点，文字作为子节点一起动）。引擎源码里 `zoomScale` 只在 `SCALE` 过渡里生效，与本次同时要"换图 + 缩小"是互斥的。
- **按下态缺失时的行为**：`Button._updateSpriteTransition` 只在取到对应态的帧时才改帧，拿不到 `pressedSprite` 就保持当前帧——所以按下态图缺失不会画出破图，只会退化成"按下不换图"（代码里告警不报错）。正常态缺失才会走占位底。
- **占位底是代码画的，编辑器里看不见**：`Graphics` 的绘制路径不序列化（与 04 号的副标题底框同一形态）。场景里留下的是节点本身与它的 `360×140`，运行时的样子在 `onLoad` 里画出来。
- **`.meta` 必须跟着图一起覆盖**：九宫格边距记在 `.meta` 的 `borderTop/Bottom/Left/Right` 里，只丢 PNG 会让边距回到 0、四角随之变形。这条已补进出图需求文档的"导入设置固定"一段。
- **与规格的两处偏差（留给 07 / 美术）**：① 交付图的画布是 2400×800（规格要 720×280），角部圆头占满半个画布，导致上面说的"九宫格没有中段"；② 两张图的尺寸也各不相同（800 / 807 高），本票给它们用了同一组边距以免按下时跳动。都属于素材侧问题，程序侧不做补偿（把边距改成不等值会让两态在按下瞬间跳一下）。
- 本票未改 `funplay-cocos-mcp.config.json` 与 `settings/v2/packages/information.json`（运行中的编辑器自己写的，与本次无关，按前几票的规矩不纳入改动）。
