# 开始页质感升级

## Problem Statement

玩家打开链接看到的第一屏（**开始页**）现在是"一张背景照 + 五行系统字体 + 一块橙色矩形按钮"：标题是 Arial 80 号白金色无描边，副标题与玩法说明是两行裸文字直接压在花哨的夜景上，最高分是一行"最高分 0"，开始按钮是一个不透明纯色方块、且**按下时毫无反应**。结果是：这一屏看上去像"开发中的调试页"而不是"一款游戏的封面"——玩家在一眼之内无法判断这是不是个正经做的、值得点开的东西。

更具体地说，玩家面对的问题有三个：

1. **标题不立**：标题是一款游戏的门面，"清补凉大师"五个字用系统字体平铺在夜景上，既不抢眼也不特别，说不出任何"海南／糖水铺"的味道。
2. **文字读不清**：副标题与玩法说明直接压在背景图上（背景还会被压暗层覆盖），对比度低、层级扁平，玩家要"努力看清"而不是"一眼读到"。
3. **没有可点的感觉**：开始按钮是纯色矩形，没有底图、没有按下反馈，玩家点它之前感受不到"可以点"，点它之后也得不到任何回应。

此外还有两个只有开发侧能感知、但会直接拖慢迭代的问题：这一屏的所有元素都散落在代码里运行时拼装，改一次版面就要跑一次预览；以及仓库里没有任何"标题艺术字／按钮底图"的资源位置与规格约定，美术一交付就会面临"放哪、多大、什么格式"的反复沟通。

## Solution

把**开始页**这一屏从"代码拼装的调试页"升级为"有设计感的游戏封面"，**只改开始页，单局页与结算页一行不动**：

- **标题区**：删掉文字标题，换成一张有设计感的"清补凉大师"艺术字图片（透明底 PNG）；图片在窄屏上按可见宽度等比缩小，绝不被切边。
- **副标题区**：文字保留，下面垫一块**圆角半透明黑色底框**，让苏轼那句"椰树之上采琼浆，捧来一碗白玉香"在任意背景上都读得清。
- **说明文字**：字号调小、颜色变淡，从屏幕中部挪到**中间偏下**，让出中间给背景的视觉焦点，也不再和标题抢戏。
- **最高分区**：加一个小**奖杯图标**，后面跟"最高分：N"。
- **按钮区**：删掉纯色矩形，换上一张**木牌／椰壳造型的底图**（配九宫格，拉宽不变形），按下时**换图并轻微缩小**；"开摊"两个字保持为按钮的**子节点**，所以按下时文字跟着一起动。

配套三件"让这次升级可持续"的事：三张图的**规格与提示词写成出图需求文档**（美术照着出、照同名覆盖交付）；开始页的静态骨架**放进场景**，改版面所见即所得（其余页维持现状，用一条 ADR 记录这个不一致的理由）；顺手把上次保存场景时被带进来的、与本次无关的 Canvas 自动布局噪音还原掉，让这次改动的 diff 只包含真正的改动。

美术资源未到位的期间，标题与按钮**用程序化／文字兜底**：今天就能看见最终版面与层级，图一到（同名覆盖文件）自动生效，不需要任何代码或场景改动。

## User Stories

1. 作为玩家，我想在第一屏看到一个有设计感的艺术字标题，这样我一眼就能感到这是一款认真做的游戏
2. 作为玩家，我想标题在任何宽度的手机屏幕上都是完整、不变形的，这样我不会看到被切掉一半的"清"字
3. 作为玩家，我想副标题有一块半透明底框垫着，这样压在花哨的夜景上我也能轻松读清
4. 作为玩家，我想玩法说明的字号小一点、颜色淡一点，这样它不会和标题抢注意力
5. 作为玩家，我想玩法说明出现在屏幕中间偏下的位置，这样中间留给背景画面、我的视线有层次
6. 作为玩家，我想最高分旁边有一个小奖杯图标，这样"这是我的纪录"这件事不用读字就能感受到
7. 作为玩家，我想看到"最高分："后面直接跟数字，这样这一行读起来像一个完整的句子
8. 作为玩家，我想开始按钮是一块有质感的木牌／椰壳，而不是一个纯色方块，这样它看起来像游戏里的东西
9. 作为玩家，我想按下开始按钮时立刻看到按钮变化（换图 + 轻微缩小），这样我知道自己点到了
10. 作为玩家，我想按下按钮时"开摊"这两个字跟着按钮一起动，这样文字和底图是一体的、不会看起来像贴歪的贴纸
11. 作为玩家，我想按钮上的文字在浅色木纹上依然清晰（有描边），这样我不会因为背景浅而读不清按钮
12. 作为玩家，我想点一下"开摊"就进入单局，这样从封面到开玩只需要一次操作
13. 作为玩家，我想从单局回到开始页时最高分立刻是新的，这样刚破的纪录不用重开页面就能看见
14. 作为玩家，我想在更长的窄屏手机上（比 9:16 更窄）看到完整的标题、副标题底框与说明文字，这样我不会因为机型被裁掉内容
15. 作为玩家，我想在横屏被压窄的桌面浏览器窗口里同样看到完整的开始页，这样我在电脑上试玩也不会看到错位
16. 作为美术交付者，我想拿到一份写清画幅、导出倍率、透明留白、九宫格准备的出图需求（含可直接复制的中英文提示词），这样我出的图不用返工
17. 作为美术交付者，我想只要把同名文件覆盖进去就能换图，这样我不必找人改代码或重连场景
18. 作为美术交付者，我想在按下态与正常态之间有明显差异的要求，这样我出的两张图能真正表达"按下了"
19. 作为开发者，我想在美术图到位之前就用文字／程序化兜底把版面做出来，这样这次改版不被素材阻塞
20. 作为开发者，我想在美术图丢失或加载失败时页面仍然显示文字兜底，这样开始页不会开天窗
21. 作为开发者，我想在场景里直接看到并调整开始页的版面（所见即所得），这样改一次间距不用跑一次预览
22. 作为开发者，我想开始页的新样式能复用仓库里已有的绘制与加载能力，而不是再造一份，这样将来给单局页换皮时是同一套入口
23. 作为开发者，我想"标题在窄屏缩到多宽、最高分行怎么居中"这类计算是纯函数，这样我可以不开编辑器就把边界情况测掉
24. 作为开发者，我想这次的 diff 里只有本次改动（不含编辑器自动写入的布局噪音），这样审查时不会被无关变更干扰
25. 作为开发者，我想仓库里那条"编辑器拒绝保存场景"的过期注释被纠正，这样后来的 agent 不会继续绕开场景去写运行时补挂的代码
26. 作为验收者，我想开始页有五条可对照的验收点（标题、副标题底框、说明文字位置、奖杯+最高分、木牌按钮与按下反馈），这样我能逐条打勾
27. 作为验收者，我想确认单局页与结算页**没有任何回归**（尤其结算页那行最高分），这样这次改动是纯粹的开始页升级
28. 作为验收者，我想看到窄屏（9:16 以下画幅）下的截图，这样适配这条不是靠推理而是有证据
29. 作为文档读者，我想有一条 ADR 解释"为什么开始页在场景里、其他页在代码里"，这样我不会以为这是疏忽
30. 作为文档读者，我想在领域词表里查到"开始页／单局页／结算页"这三个界面状态，这样文档与代码不会各说一套
31. 作为素材作者，我想三张新图被登记到素材来源清单里（来源与授权），这样署名义务被履行
32. 作为维护者，我想这次的实现拆成一张张独立 ticket，这样进度可追踪、不必一口气改完

## Implementation Decisions

**范围与装配策略**

- 本次**只改开始页**：单局页、结算页、背景层、所有反馈层的表现层一律不动，包括结算页那行最高分。
- **装配策略（写一条 ADR）**：开始页的静态骨架进场景、由编辑器所见即所得地调整；其余页面对应的运行时装配方式**保持现状**。理由是这次愿意动场景的唯一动机是"开始页要反复调版面"，而单局页是动态布局（拖拽跟手、随机图标、计时重排），迁移收益低而踩坏自适应逻辑的风险高。这条不一致是自觉取舍，不是遗留疏忽。
- 既有的"编辑器拒绝保存场景、只能在运行时补挂组件"这条注释已过期（实测可保存），**只纠正注释与措辞，不改行为**。

**版面（设计分辨率 720×1280，`FitHeight`，节点坐标以页面中心为原点）**

| 元素 | 纵向位置 | 说明 |
| --- | --- | --- |
| 标题艺术字 | 330 | 设计尺寸 560×160，运行时按可见宽度等比缩放 |
| 副标题（含底框） | 205 | 文字 30 号；底框圆角 16、黑色 45% 透明、内边距水平 28 / 垂直 14 |
| 玩法说明 | −230 | 22 号、颜色更淡；落在背景的底部安静区 |
| 最高分（奖杯 + 文字） | −330 | 奖杯 44×44、与文字间距 10，整行水平居中 |
| 开摊按钮 | −490 | 底图 360×140 |

**标题**

- 删掉文字标题，改为一个 Sprite 节点承载艺术字图片；**同时保留一个文字节点作兜底**：加载到图片就显示图片、加载不到就显示文字（兜底文字用系统字体、金色、与旧标题同字号）。
- 标题**不按 720 满宽设计**：适配事实是 `FitHeight` 下 9:16 全面屏只看得见约 590 设计像素宽，因此设计宽定为 560，且运行时按"可见宽度 − 两侧各 60"为上限**等比缩放**（只缩不放），保证窄屏不切边、宽屏不虚胖。
- 图片导入约定：**不裁剪**（保留原始画布，否则五字被裁会导致定位漂移）、**不参与自动图集**（避免将来开启图集时边缘渗色）。

**副标题底框**

- 程序化绘制圆角矩形（引擎的 `Graphics.roundRect` 在 3.8.8 可用），**不出图**：这块的价值是"让文字读得清"，程序化已经完全够用。
- 底框宽度**跟随文字盒宽**，与玩法说明共用同一个收窄来源（当前可见宽度），保证窄屏下"框不会比字宽、也不切字"。
- 底框节点在渲染顺序上位于文字**下方**。

**最高分行**

- 改造成一个"行容器 + 奖杯图标 + 文字"的结构；整行（图标宽 + 间距 + 文字宽）水平居中，因为最高分位数会从 1 位变到多位，居中必须随文字实际宽度重算。
- 文案改为独立的开始页专用串（"最高分："带全角冒号），**结算页继续用原有的、不带冒号的共用串**——本次不污染结算页。

**开始按钮**

- 删掉按钮自身的纯色绘制组件；换成带九宫格（9-slice）的底图 Sprite，节点尺寸 360×140，拉伸时四角装饰不变形。
- 按钮过渡方式改为 **Sprite 两态**（正常 / 按下），**不提供悬停态图**：手机端没有悬停，出一张只在桌面鼠标上生效的图不值得，悬停复用正常态。
- 按下时**额外做轻微缩小**（0.95 量级）：手机上没有悬停，玩家对"按下有没有反应"的全部感知就来自这一瞬间的画面变化。
- "开摊"文字**保持为按钮的子节点**（现状已如此），因此按下时文字与底图一起动；同时**开启引擎原生文字描边**（深棕、3px 量级），否则白字压在浅木纹上读不清。按钮文案仍来自集中文案表，不散落。

**素材与交付**

- 三张图由**项目自备（用户交付）**，符合素材授权策略（只用授权明确的素材）；**本次不启用 AI 生成**——现有 ADR 已把 AI 生成列为"版权归属不明、仅作后备手段"，若日后要改用它，先改那条 ADR。
- 资源放在可按文件名加载的资源目录下新增的界面美术子目录，**同名覆盖即换图**：同路径覆盖图片时其导入标识不变，因此场景引用不会断，这条"换图不回编辑器"的既有约定继续成立。
- 三张图的规格：艺术字 560×160（导出 2 倍即 1120×320，四周留 20px 透明，图上不自带阴影／外发光）；按钮底图 360×140（导出 2 倍即 720×280，四角装饰控制在边角 60~80px 内，中间为可拉伸平纹）；奖杯 44×44（导出 2 倍即 88×88）。全部为透明底 PNG。
- 新增**出图需求文档**（照既有的背景出图需求格式：规格表、可直接复制的中英文提示词、收图检查清单、交付路径）；新图登记到素材来源清单（含来源与授权）。

**复用与代码边界**

- 圆角面板绘制**扩展现有的界面绘制工厂**（不新造一套画板）；界面图片加载**从配料图标模块中提取成通用入口**（不出现第三份重复的加载代码）。
- "标题缩放宽度"与"最高分行居中排布"抽成**不依赖引擎的纯函数**，放在界面层但保持无引擎依赖，供测试直接调用。

**文档**

- 新增 ADR：记录"开始页进场景、其余页运行时装配"的取舍与代价。
- 领域词表补三个界面状态：**开始页 / 单局页 / 结算页**（把代码里的英文页名列为避免用法），词表用词与设计基线、README 的现有用词保持一致，不另造方言叫法。
- README 的目录结构与素材来源清单补上新的界面美术子目录与三张图。
- ~~标题文案串在文案表中**保留**，并注明"与艺术字图片的内容对应，改文案需重出图"——它是图片内容的文案镜像，删掉会让"图片上是五个字、文案表里是另一串字"的漂移无从察觉。~~ **（2026-09-22 撤销：`title` / `subtitle` / `howToPlay` 三个键已全删，当时的理由随元素化骨架一起作废，见下方"后续整体推翻"）**

**一次性清账**

- 动手前先还原上一次保存场景时被编辑器写进来的 Canvas 自动布局值（位置与内容尺寸），使本次 diff 只包含真正的改动。

## Testing Decisions

**什么是好测试**：沿用仓库既有约定——只断言**外部行为**：给定输入，断言输出，不碰内部字段、不 mock 内部协作对象。测试名用中文写成一句需求，读起来就是验收标准。

**接缝选择**：本特性几乎全在表现层，而仓库里唯一能廉价自动化覆盖的接缝是"不依赖引擎的纯函数"。因此本次**只新增一个接缝**：把两处**易错且会静默出错**的计算抽成纯函数——① 标题在给定可见宽度下的等比缩放宽度；② 最高分行的整体居中排布（图标宽、间距、文字宽 → 各元素横向位置与总宽）。这两个函数**不 import 引擎**，可见宽度由调用方作为参数传入（引擎只负责提供这个数）。渲染、场景接线、九宫格、按钮过渡、文字描边这些**不写自动化测试**，走手动验收。

**被测模块**：仅上述纯函数模块（无引擎依赖）。开始页视图组件、界面绘制工厂、图片加载入口都不测——它们要么依赖引擎，要么只是把参数转发给引擎。

**先例**：`tests/session.test.ts` 建立的约定——测试文件放引擎编译范围之外、用 vitest 从根目录跑、固定输入保证可复现、测试名是中文需求句。本次照此办理，新增一个测试文件。

**必须覆盖的行为**

- 可见宽度 ≥ 设计宽度时，标题宽度等于设计宽度（宽屏不被放大也不缩小）
- 可见宽度 < 设计宽度时，标题等比缩小且不超过"可见宽度 − 两侧留白"；两侧留白为负余量的极端窄屏（如 320）不产生负数或越界结果
- 缩放是**等比**的（高宽比保持），且只缩不放
- 最高分行的总宽等于"图标宽 + 间距 + 文字宽"；文字位数从 1 位变到多位时整行仍居中（左右两端到容器中心的距离相等）
- 边界：文字宽为 0、或"图标 + 间距"已占满容器时，输出仍是有限的确定值（不返回 NaN／Infinity）

**手动验收**（自动化覆盖不到的部分）

1. 开始页五处元素呈现新版面（标题、副标题底框、说明文字位置、奖杯 + 最高分、木牌按钮）
2. 按下"开摊"：底图切换 + 轻微缩小，"开摊"二字跟着一起动
3. 把编辑器的 Game View 拖窄到比 9:16 更窄：标题与副标题底框都不被切、说明文字不被裁
4. 单局页与结算页无回归（重点看结算页那行最高分仍是旧文案、数值正确）
5. 图片槽位为空时开始页显示文字兜底、不开天窗
6. `npm test` 与类型检查通过；引擎脚本诊断 0 错误
7. 编辑器截图作为验收证据留档

## Out of Scope

- 单局页与结算页的质感升级（纯色面板、进度条、碗、配料盘换皮）——本次只做开始页
- 12 格配料图标的替换（仍是 Fluent Emoji，6 格近似图标 + 中文标签兜底的问题不动）
- 音频（BGM 与音效，仓库既定不做）
- 自定义中文字体／字体子集化（本次标题用图片，正文仍系统字体）
- 入场动画、粒子、背景视差等表现层升级（本次只有按钮按下缩放）
- AI 生成素材（要动用先改素材授权 ADR）

## Further Notes

**为什么先做开始页**：开始页是玩家唯一"还没决定要不要玩"时看到的一屏，质感不足的代价最高；而它同时是风险最低的一屏——没有玩法状态、没有拖拽、没有计时，改坏了也不影响任何规则。

**已知交付风险（来自同类素材的历史教训）**：上一批背景图交付时出现过两处必须逐张验收的问题——图里带生成工具水印、以及其中一张其实是带手机状态栏的截图。因此本次收图检查清单里必须包含"无水印、无设备界面元素、四周透明留白到位"这几条，且每张图都要在 720×1280 的缩放下看一眼。

**已知工具风险**：编辑器会按当前 Game View 画幅自动回写 Canvas 的布局值。因此**每次保存场景后都要检查 diff**，确认没有夹带这类噪音；这也是本次要求"动手前先清账"的原因。

**开放项（不阻塞）**：三张美术图待用户交付；期间标题用兜底文字、按钮用程序化底图，版面与层级当天即可验收。图片到位后只需同名覆盖文件，不改代码、不改场景。

**接缝确认点（需用户确认）**：本次新增的自动化接缝只有"标题缩放宽度 + 最高分行排布"这一个纯函数模块。如果你认为这两处不值得单测（宁可全部走手动验收），实现时可以退化为零新增测试、只保留手动验收清单；两种做法的实现范围差异仅在那一个模块与一个测试文件。

**下一步**：本次只发布 spec。实现拆成 ticket 放到同目录 `issues/` 下逐张推进（编号从 `01` 起，一文件一张，不合并）。

## 实现偏离注记

实际落地与上面 spec 有几处**有意偏离**（用户验收时判定原开始页太难看，主动调整了质感方向）。记录在此，避免后来的人照 spec 返工：

- **关闭整屏背景压暗（`backgroundDim` alpha 175 → 0）**：spec 的「范围策略」写明"背景层一律不动"，Problem Statement #2 也假设"背景会被压暗层覆盖"。实际实现把全局压暗关掉了——质感升级后改由各元素自带底框（如 `subtitleBackdrop`）托文字，让背景美术透出来。这是越出 spec 原定范围的改动，按用户意图保留；要恢复全局压暗把 alpha 调回 175 左右即可。
- **玩法说明颜色更亮（非"更淡"）**：spec 要求"颜色更淡"（表 `玩法说明 | −230 | 22 号、颜色更淡`，User Story 4），实际渲染色从 `(150,162,182)` 改为 `(252,252,252)`（更亮、更跳）。用户有意让说明文字更醒目。
- **玩法说明位置上移（非 −230）**：spec 定位于 `y = −230`（屏幕中间偏下、底部安静区），实际 `y = −190`（更靠中心）。用户有意调整。
- **标题 Sprite / 文字兜底节点对调**：spec 只要求"Sprite 承载艺术字 + 文字节点兜底"，结构仍满足；组件在两节点间互换归属属编辑器内重连，spec 无此要求，仅为落地时的接线方式，不影响行为。
- **后续整体推翻（2026-09-22，见 `docs/adr/0004-start-page-cover-art.md`）**：本 spec 的"版面"整节（标题艺术字 / 副标题与其底框 / 玩法说明）已被**整块取代**——开始页换成一张把标题与副标题都画进去的整屏封面图，这五类节点从场景里删除，`title-art.png` 也从仓库删除。本次 spec 造出的元素化骨架不再存在；最高分行与开摊按钮保留（坐标由 −330 / −490 改为 −430 / −545）。也就是说，**不要再照本文件的版面表去改开始页**。

> 偏离本质：spec 的质感方向偏"克制、压暗、文字后退"，实际落地偏"明亮、背景透出、文字更跳"。两者都是有效设计，差异来自用户最终审美取舍，非实现 bug。
