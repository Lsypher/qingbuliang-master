# 准备过场

## Problem Statement

玩家点「开摊」或「重开」之后，游戏**立刻**切进单局页并开始跑 60 秒倒计时。手还没放稳，第一位顾客和计时就已经开始了——60 秒里的前一秒多，玩家其实是在适应画面变化，而不是在玩。

更糟的是，那一刻页面上该有的图**全都还没开始加载**。单局页（连同它下面的配料盘、订单卡、碗）在场景里长期处于隐藏状态，而节点隐藏时其组件的 `onLoad` 根本不会执行——所以那 12 张配料图标是在玩家**已经进入单局页之后**才发起加载的；本局那张背景图也是切页广播到达的那一刻才换。玩家看到的是：刚进页面，配料盘格子是空的、图标一张一张往外冒，背景"啪"地跳一下。

两个问题：

1. **没有准备时间**：点下去就开跑，玩家在开局的头一秒是在适应画面变化，而不是在玩。
2. **图片在眼前加载**：本局要用的背景与 12 个配料图标都在进入单局页之后才开始加载，延迟肉眼可见。

## Solution

在开始页／结算页与单局页之间横一段**准备过场**：全屏、无按钮、不可交互。它同时做两件事——用一段固定节拍给玩家准备时间，并在这段时间里把本局要用的图先加载好。

过场结束时单局才真正开始计时。玩家看到单局页的第一帧就是 60 秒满格、背景与本局 12 格配料图标全部就位。开摊与重开两条路径共用同一段过场。

过场本身由代码绘制（一条扫动的进度条 + 一句文案），不依赖任何尚未加载的美术资源——否则它会自己卡在"等自己"上。

## User Stories

1. 作为玩家，我想点下「开摊」之后先看到一段过场而不是立刻开跑，这样我有时间把手放稳、知道"马上要开始了"
2. 作为玩家，我想点下「重开」之后同样看到这段过场，这样每一局的起跑条件是一样的
3. 作为玩家，我想看到单局页的第一帧就是 60 秒满格，这样我不会怀疑"计时是不是已经偷跑了一点"
4. 作为玩家，我想过场期间倒计时完全不推进，这样这段准备时间不从我的这一局里扣
5. 作为玩家，我想进入单局页时背景已经就位、不"啪"地跳一下，这样我的注意力不会被无意义的画面变化打断
6. 作为玩家，我想进入单局页时 12 格配料图标已经全部就位，这样我不用盯着空格子等图标一张张冒出来
7. 作为玩家，我想过场不长到让我不耐烦（约一秒出头），这样"准备"不会变成"等待"
8. 作为玩家，我想过场即使遇到加载慢也不会一直卡住（有上限），这样我不会被永久困在一片加载画面里
9. 作为玩家，我想过场期间不管怎么划、怎么连点，都不会影响到后面的对局，这样我乱点的代价不会是"白白丢掉一局"
10. 作为玩家，我想连点两下「开摊」也只开一局，这样我不会莫名其妙地少掉开局的几秒
11. 作为玩家，我想过场出现在结算页上时看起来是"这一局收尾了"，而不是"又多了一屏要读"
12. 作为玩家，我想过场上的文字是中文、语气与游戏一致，这样它不像系统加载画面
13. 作为玩家，我想在比 9:16 更窄的手机上也能完整看到过场内容，这样我不会看到被裁掉一半的进度条
14. 作为玩家，我想过场里没有任何需要我点的东西，这样我不会在"准备"的时候被迫做决定
15. 作为开发者，我想过场不是第 4 个界面状态、而是盖在页面之上的过场层，这样"三个界面状态互斥"这条不变式不用动、切页逻辑也不用改
16. 作为开发者，我想放行判据（什么时候可以进单局页）是一个不依赖引擎的纯函数，这样它能被单测覆盖，而不用开编辑器去试时序
17. 作为开发者，我想最短展示时长与超时上限是配置常量，这样"觉得难受就改常量"而不是改逻辑
18. 作为开发者，我想"本局背景"在过场开始前就抽定，这样过场预载的就是这一局真正要显示的那张，而不是下载了 4 张只用 1 张
19. 作为开发者，我想背景池与随机源的知识仍留在背景层，这样组合根不会被塞进"知道有哪些背景"这件事
20. 作为开发者，我想过场期间底下的按钮即使看不见也点不到，这样"过场不透明、手指却穿过去"这类 bug 不会出现
21. 作为开发者，我想预载失败或超时就直接放行、沿用既有的缺图兜底，这样不会为同一件事写第二套兜底逻辑
22. 作为开发者，我想统一配色表与既有的绘制工具能被过场复用，而不是新起一套样式
23. 作为开发者，我想过场层在运行时装配到画布最上层，这样场景文件只多出最小改动，不需要回编辑器接线
24. 作为开发者，我想仓库里那条"本仓库无 git 远程"的过时描述被纠正，这样后来的 agent 不会据此误判 issue 该记在哪里
25. 作为验收者，我想有 8 条可逐条打勾的验收点（见 Further Notes），这样我能确认这次改动没有把既有的缺图兜底改坏
26. 作为验收者，我想确认开始页与结算页**没有回归**，这样这次改动是纯粹地插入了一段过场

## Implementation Decisions

- **形态**：准备过场是**过场层**，不是第 4 个界面状态。它盖在当前界面之上，出现时底下的页面仍在场；「三个界面状态互斥显示」这条不变式与切页逻辑都不动。与 ADR-0002 对"纯表现覆盖层运行时装配"的立场一致。
- **唯一新增测试缝**：放行判据放进 `core` 层（无引擎依赖），是这次唯一的新测试缝。其余改动都落在既有的表现层与适配层内部，不加新缝。
- **放行判据的形状**：它只认时间与"已决数"，**不区分成功与失败**——失败与成功对"能不能进单局页"这个判断没有影响。这个类型形状是本次 grilling 定下的：

  ```ts
  decideEntry(
    elapsedMs: number,
    settled: number,
    total: number,
    limits: { minShowMs: number; timeoutMs: number },
  ): 'wait' | 'go'
  // go ⟸ (settled >= total && elapsedMs >= minShowMs) || elapsedMs >= timeoutMs
  ```

- **节拍**：`max(最短展示 1200ms, 预载完成)`，另加 3000ms 硬超时。最短展示从**过场出现那一刻**起算；超时是"从过场出现到必须放行"的总时长上限。两个数值都是 `config` 层的常量。
- **失败与超时的兜底**：任一项加载失败或整体超时即放行，缺图沿用既有兜底——背景保留旧图、配料图标跳过这一格。不为过场另写一套兜底。
- **预载范围**：只预载**本局真正要用的那一张背景** + **全部 12 个配料图标**。不预载背景池里的其余几张：4 张 1080×1920 同时常驻的内存代价已有结论（背景层只留当前一张），不值得为一个更快的下一局把它翻过来。
- **抽图拆两步**：背景池与随机源的知识留在背景层。原来"抽图"与"显示"是同一步，现在拆开——组合根在过场开始前让背景层先抽定本局背景并取回路径，过场预载它，过场结束时背景层显示这张已抽好的图、不再重抽。
- **交接时序**：过场保持不透明到最后一帧，然后**同一帧内**依次：切页 → 开一局新的 → 熄过场。**不做淡出**——淡出要么让玩家先看到旧页，要么让倒计时在玩家还没看清单局页时已经开始跑。过场的"结束感"由过场内容自身收尾提供，不由页面过渡提供。既有切页与新开一局那两步的顺序与内容都不变，只是被过场的亮起与熄灭包住。
- **为什么计时必须晚启动**：单局计时由"开一局新的"这个动作建立（`剩余时间` 被初始化为单局总时长）。把它放在过场之后，准备时间自然不占用 60 秒，不需要额外机制；过场期间单局页仍隐藏，其组件不参与逐帧推进，计时器也不可能偷跑。
- **输入封锁与幂等**：过场层整屏吃触摸（挡掉过场期间落在下层按钮上的点击），同时组合根加一个"正在进入"的幂等标志（挡住过场刚熄、页面刚切那一两帧内的连点）。两者不重复：一个挡空间上的穿透，一个挡时间上的重复。
- **素材来源**：过场由代码绘制，不新增美术交付。不定式扫动条复用既有的绘制工具与统一配色；只有文案进 `config` 的文案表。这与开始页当初"程序化兜底先上、真图到位后同名覆盖"是同一条路。
- **文案**：暂定"正在备料…"，**不带海南味**——方言配额（克制在 3~5 处）已给结算页与连击，要在这里用方言需从别处挪一个出来。
- **装配方式**：过场层由组合根在运行时装配到画布最上层（与背景层、反馈层同一套路），场景文件只多出最小改动。
- **文档**：决策记 `docs/adr/0003-prepare-transition.md`；`docs/design/mvp-spec.md` 的界面小节补一行；细节留在本文件。

## Testing Decisions

- **什么算好测试**：只测外部行为，不测实现细节。放行判据的测试只断言"给定时间与已决数，返回放行还是等待"，不断言内部用什么公式算；不 mock 引擎、不 mock 定时器——时间与已决数都是入参。
- **测哪个模块**：`core` 层的放行判据。这是本特性唯一被测的模块，也是仓库里唯一被测的层。
- **先例**：`tests/` 下已有的两个纯逻辑测试（单局规则核心、开始页版面的纯函数）——同样的写法：纯函数、表驱动、不碰引擎。
- **覆盖的四条分支**：
  1. 未到最短时长且预载未完成 → 等待
  2. 预载已完成但未到最短时长 → 等待
  3. 预载已完成且已过最短时长 → 放行
  4. 整体超时（无论预载状态）→ 放行
- **不测什么**：表现层（过场动画、装配、吃触摸、交接时序）不在测试范围内——仓库的表现层零测试是既定的代价，这次不改变它。

## Out of Scope

- 真进度条与百分比（本地 bundle 的加载进度会跳变，收益为负）
- `3-2-1` 准备倒计时
- 过场的新美术出图（先用代码绘制）
- 预载背景池其余几张、跨局缓存策略
- 其它页面之间的过场
- 音频

## Further Notes

- **验收点（8 条）**：
  1. 点开摊后，过场期间倒计时不在推进；过场结束时单局页一出现就是 60 秒满格
  2. 首次进入单局页时，背景与 12 格配料图标**不再逐格弹出**
  3. 过场从出现到消失 ≥1200ms；本机 ≤3000ms
  4. 过场期间连点开摊／重开，不会连开两局
  5. 结算页点重开走同一套过场（同样 ≥1200ms）
  6. 把一张背景图改名后，过场仍按时放行、背景保留旧图（兜底没被改坏）
  7. `core` 放行判据的单测覆盖四条分支
  8. 窄屏（可见宽约 590）下过场排版不被裁切
- **首次进入与重开的体感不同**：第一次开摊时配料图标从未加载过，预载真的会花时间；之后每次重开都是缓存命中，预载几乎瞬间完成，实际只花 1200ms 固定节拍。这是"两条路径共用同一套节拍"的必然结果，不额外做特例。
- **不要顺手把编辑器回写噪声夹进提交**：ADR-0002 已提醒过，保存场景会回写 Canvas 自动布局与"当前显示哪一页"的 `active` 状态，这类 diff 与本次无关。
- **顺带纠正的文档**：`AGENTS.md` 原文写"本仓库无 git 远程"，与实际不符（有 GitHub 远程），一并在本次改掉。
