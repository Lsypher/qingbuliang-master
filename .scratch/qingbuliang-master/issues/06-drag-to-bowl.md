# 06: 拖得动——拖拽入碗

**What to build:** 从配料盘把配料拖进碗：配料跟手、碗在拖动期间高亮、松手时判定落点（落区带容差）；点按依旧可用。

- [x] 拖动期间碗高亮，松手后恢复
- [x] 落在碗区域内（含边缘容差）算放入，落在别处则配料归位
- [x] 点按与拖动两种方式行为一致

## Comments

- **分层**：配料盘只识别手势（点按 / 拖动 / 打断），经总线 `DragMoved` / `DragEnded` / `DragCanceled` 上报"拖着谁、松手在世界坐标哪里"；适配层 `GameSession` 做落点几何判定（落区 = 碗区节点中心 + 配置尺寸 + 容差 40px），翻译成核心 `drop()` 与表现层 `DragOverBowl` 事件；碗视图只听后者画高亮。配料盘依旧不认识碗，碗依旧不做判定。
- **跟手的实现**：幽灵节点起手锚在源格子中心，之后每个 move 事件叠加 `getUIDelta()`（UI 坐标增量，与坐标原点无关），松手位置取幽灵的 `worldPosition`——全程引擎原生坐标系，不引入"UI 坐标系原点在可视区左下角"这类换算陷阱。
- **落区与高亮同源**：落区尺寸 `BOWL_DROP_ZONE_WIDTH/HEIGHT`（600×380）收在 `config/layout.ts`，高亮框与判定矩形都从它取值；判定再外扩 `DROP_ZONE_TOLERANCE_PX`（40）。落区比三段布局的碗区面板（720×510）小一圈，底边不会探进配料盘顶行、顶边不会贴上订单卡。
- **点按与拖动并存**：手指挪动超过 8px 才算拖动，否则交给格子 Button 的 click 原路径（自检的 `emitClick` 也依赖它）；拖动途中 Button 仍会在松手时发 click，`onSlotClicked` 用"已进入拖动"拦截，避免同一份配料进两次碗。
- **顺手修正的既有问题**：配料盘三行原按 0/-118/-236 排布，第三行（芒果丁、通心粉、仙草冻、鹌鹑蛋 4 格）整体落在 720×1280 可视区之外、无法点也无法拖；现改为三行以托盘中心对称排开（±118），上下各留 14px 空隙。
- **运行期验证**：`SelfCheck` 新增 6 条拖拽断言（悬停高亮开/关、落碗接受且进度 +1、碗外松手进度不变且高亮熄灭），以世界坐标直接驱动总线事件，走的是真实适配层链路；加黑盒模拟触点做不了"跟手"，手感请在预览里手动拖一次复核（Game View 截不到动态画面）。
- **评审整改**：抽掉 BowlView 与 OrderCard 里逐字重复的 `ingredientName`（集中到 `config/ingredients.ts`）；删除无人调用的 `getSlotNode`；页面失活/组件销毁时的拖动兜底复位（`onDisable` → 按打断收尾，高亮不带到下一局）补记于此；click 拦截对监听注册顺序的依赖已写进代码注释。
- 核心层零改动：21 个 vitest 用例原样全绿；`npx tsc -p tsconfig.json --noEmit`（TypeScript 5.4）0 错误。
