# 10: 有张力——得分、连击与倒计时反馈

**What to build:** 出餐时飘出本单得分、顶栏显示连击数、连到 3 连时冒出"够劲！"、订单卡上已放入碗中的项打勾变暗、最后 10 秒倒计时变红脉冲。

**Blocked by:** 04

**Status:** done

- [x] 得分飘字数值与核心给出的本单得分一致
- [x] 订单卡能看出"还差哪几项"（已放入的变暗打勾）
- [x] 3 连起出现"够劲！"，错放断连击后不再出现
- [x] 最后 10 秒倒计时变红脉冲，且每局只触发一次

## Comments

**规则层一行没动**：核心早就给全了——`served` 事件带 `orderScore`（本单得分，含连击加分）与 `comboCount`，`countdownWarning` 每局只发一次（`state.warned` 是它的可读镜像）。所以本切片不改 `core/`、不加用例：验收点全在"表现层怎么读这些数"。顶栏的连击数在 03 切片就已在 `HudLine` 上（分数 / 完成订单 / 连击），本次只补断言。

**落了什么**

- `ui/ServeFeedback.ts`（新增）：出餐瞬间在碗口上方飘出本单得分（`+40`），上飘 + 淡出，节点用完即焚；连击 ≥ 门槛再冒一句"够劲！"（弹入 → 停留 → 淡出）。数值直接取事件里的 `orderScore`，视图不算分。
- `ui/OrderCard.ts` + `ui/ingredientIcon.ts`：`renderIconRow` 多了可选的 `checkedIds`——命中的图标压暗（只压精灵 alpha，勾保持亮）+ 右上角打勾。碗里不传这个参数（碗里的本来就是"已放入"）。
- `ui/HudView.ts`：告警只认核心的 `warned`——翻真就把数字与进度条一起转红并开始缩放脉冲，新一局回落为假即复位。镜像核心状态而不是自己计时，"每局只触发一次"是白拿的；只在翻转时动一次，脉冲不会被反复重启按在原地。
- `config/balance.ts` 的 `COMBO_SHOUT_AT = 3`：喊话门槛是纯表现阈值（不影响计分），按分层放数值配置、由表现层读，不下沉到规则核心。
- `ui/uiFactory.ts`：抽出 `createOutlinedText`（暗色垫底 + 亮色正文），错放的"-3 秒"飘字改用它与得分飘字共用一套；`paintPanel` 支持重复调用重画（进度条转红要用）。

**装配方式**：`ServeFeedback` 与错放反馈一样，由组合根 `GameRoot.assembleGameFeedback()` 在运行时补挂到单局页——编辑器仍拒绝保存场景改动（见 09 的遗留问题）。编辑器恢复后改成在场景里给 `GamePage` 挂组件，删掉那一步即可。

**运行期验证**：Game View 自检 **79/79 全绿**（本切片开工前的基线是 59/61）。新增断言：得分飘字数值 = 核心给出的本单得分（拿 HUD 分数增量核对，带连击加分的单也核对）；订单卡已放入的项有勾且精灵 alpha 明显压低（< 200，实际 110）、未放入的保持原样；1 连 / 2 连不冒"够劲！"、3 连冒出、错放断连击后紧接着那一单不再冒、"够劲！"会自己消失；10 秒之前倒计时不变红不脉冲、最后 10 秒变红且缩放确实在动（采样 0.48 秒取最大缩放）、重开一局复位。

**顺手修了两条本来就红的自检断言**（都不是游戏缺陷，是本切片期间撞见的既有问题）：

1. `拖进碗里的配料被接受` 读的还是"碗中"文字标签，而 08 切片把碗改成图标行了——标签在非空时恒为空串。改成读 `BowlIcons` 的图标行；`重复放入同一配料：碗内容不变` 同理（原先两边都是空串，恒真）。
2. `同一局内背景不切换` 取样太早：背景是异步加载的，进局后约 150~450ms 新图才到位，此前屏幕上仍是上一张（避免闪空，有意为之）。自检在第 0.3 秒就取样，把"加载窗口"读成了"中途换图"。改成先让出加载窗口、等连续两次采样一致再取基准。临时日志量过请求→回调的时序：150~441ms、按请求顺序返回，未发现旧回调覆盖新图（不是竞态）。

**已知取舍**：得分飘字锚在碗心上方 120（设计像素）并上飘 40，"够劲！"锚在碗心上方 250——按字号折算，飘字末端的字面停在 163 上下、"够劲！"的字面从 191 起，两者不叠（早先两处参数会让它们叠上，评审后已改）。"够劲！"的字面底边 259 与进度行"已放 n / m"的字面顶边 267 留 8 像素，也不打架。冒出来的时机正是出餐的 0.4 秒过渡期，碗这时是空的，不挡玩家要看的订单信息。

## 评审（Standards × Spec 双轴，改动未提交，基准 = HEAD 083c4df）

**Standards 轴**：

- **违反"禁止重复封装"（已修）**：`ServeFeedback` 里的"世界坐标 → 本节点局部坐标"与"飘字上飘 + 淡出 + 自销毁"和 `MisdropFeedback` 里的几乎逐字重复。两段都下沉到 `ui/uiFactory.ts`（`toLocalPoint` / `floatAway`），错放与出餐反馈共用；错放飘字的行为不变（时长、距离、销毁时机都没动）。
- **同形工具重复（已修）**：自检里 `findNewestNode` 与 `findNode` 只差遍历方向、`iconRowIds` 与 `orderRequiredNames` 是同一段 `Icon_<id>_<index>` 解析的两个变体 → 合并成 `findNode(root, name, newest)` 与 `iconRowIds`（订单卡的名字由它映射得到）。
- **只取第一条出餐事件（已修）**：`ServeFeedback` 原用 `find` 只消费一条 `served`，改成遍历本帧全部事件——同帧两次出餐也各给一次反馈。
- **文档不实（已修）**：`strings.ts` 的"连击达到 3 连时冒出"把门槛写死在注释里，改成指向 `balance` 的常量。
- **未改（判断）**：`COMBO_SHOUT_AT` 放 `balance.ts` 而非组件内，与 `SCORE_FLOAT_FONT` 这类就地常量的做法并存。保留理由：它是"游戏手感阈值"、和 `COMBO_BONUS_*` 一起调，且设计基线要求"数值写成 TS 配置"；字号/动画时长属于组件私有排版参数，两者不同类。

**Spec 轴**：未发现缺失或越界的验收点；指出并已修正的只有上面那条"两处反馈不叠"的不实说法。另记两条既有缺口（不属本切片、未处理）：

- 设计基线"订单卡片：顾客 emoji 头像 + 汤底图标 + 小料图标行"（`docs/design/mvp-spec.md:33`）里的**顾客头像全仓未实现**，也没有任何 ticket 覆盖它。
- `同一局内背景不切换` 那条断言的根因仍在 09 的地盘：`BackgroundView` 不报"本局抽到哪张"、回调也没有序号，自检只能靠"让出加载窗口"绕过去（容忍约 1.2 秒以内的加载，见 `settleBackground` 注释）。真要根治得让背景层给出可读的"本局选中的那张"或给回调加序号丢弃过期结果。
