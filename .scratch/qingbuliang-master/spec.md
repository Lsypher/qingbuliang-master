# 《清补凉大师》MVP

## Problem Statement

想玩到一款"海南味"的小游戏：打开就能玩、不用教程也能上手、60 秒见分晓。玩家面对的问题是——市面上甜品类小游戏的题材几乎都是西式烘焙或奶茶，海南清补凉这种"汤底 + 一堆小料自己配"的饮食文化天然适合做成配对玩法，却没人做；而现有的拖拽类小游戏要么规则太浅（拖对就完事），要么规则太碎（十几种机制叠在一起，60 秒里学不会）。玩家想要的是：**一眼看懂在干什么、手上有事做、每一单都算得出自己为什么得这么多分**，并且玩完能说出一句"这是海南的东西"。

## Solution

一款竖屏 H5 小游戏：屏幕中间是碗，顶部是顾客的订单——恰好一种**汤底**（椰奶 / 椰子水 / 红糖水）加 3~5 种**小料**（红豆、芋圆、西瓜丁……）。玩家从底部 12 格**配料盘**里把配料拖进碗里（也支持点按飞入），**凑齐即自动出餐**：顺序无关的集合匹配，得分、连击、换下一位顾客。拖错配料是**错放**——扣 3 秒、配料弹回、连击清零。**60 秒一到结算**，分数、完成订单数、最高连击、是否破纪录，一键重开。

难度在单局内自然爬坡：前 20 秒订单要 3 种小料，20~40 秒要 4 种，最后 20 秒要 5 种。每局随机一张海南背景——骑楼老街夜市、清补凉摊、椰林海岸黄昏、黎锦纹样——让"海南"不只是题材标签，而是每一局的舞台。

## User Stories

1. 作为玩家，我想打开链接就看到开始页和标题，这样我才知道这是什么游戏、要不要玩
2. 作为玩家，我想在开始页看到我的最高分，这样我知道这次要破的是什么纪录
3. 作为玩家，我想在开始页看到一句话说明怎么玩，这样我不用看教程就能开始
4. 作为首次进入的玩家，我想在配料盘上方看到"把配料拖进碗里，凑齐即出餐"的提示，这样我第一单不会瞎试
5. 作为玩家，我想在首单出餐后让引导提示自动消失，这样它之后不会一直挡着我
6. 作为玩家，我想点一下"开始"就进入单局，这样我不必再点第二次
7. 作为玩家，我想在每一局开始看到不同的海南背景，这样反复玩不会腻
8. 作为玩家，我想看到顶部有一个 60 秒倒计时，这样我知道还剩多久
9. 作为玩家，我想在最后 10 秒看到倒计时变红脉冲，这样我会立刻紧张起来
10. 作为玩家，我想在顶部看到当前分数和连击数，这样我能判断自己打得怎么样
11. 作为玩家，我想看到顾客的订单卡片——一个头像、一种汤底、若干小料，这样我知道要做什么
12. 作为玩家，我想让已经放进碗里的项在订单卡上打勾变暗，这样"还差什么"一眼可见
13. 作为玩家，我想从配料盘把配料拖到碗里，拖的时候配料跟着我的手指，这样操作是跟手的
14. 作为玩家，我想在拖动时看到碗高亮，这样我知道松手会落在碗里
15. 作为玩家，我想点一下配料就让它飞进碗里，这样小屏上不用每次都拖
16. 作为玩家，我想在碗里看到已放入的配料，这样我确认自己放了什么
17. 作为玩家，我想在放入顺序和订单不一致时照样能出餐，这样我不必记住顺序
18. 作为玩家，我想在凑齐的瞬间自动出餐并立刻换下一位顾客，这样节奏不会断
19. 作为玩家，我想在出餐时看到得分飘字，这样我立刻知道这一单值多少
20. 作为玩家，我想把不需要的配料拖进碗里时被扣 3 秒、配料弹回，这样错误有代价但不会搞坏我碗里的东西
21. 作为玩家，我想在碗里已有同一配料时再拖一次不扣时间、静默拒绝，这样手滑连点不会重罚
22. 作为玩家，我想在错放时看到屏幕边缘红闪和"-3s"飘字，这样我知道发生了什么
23. 作为玩家，我想让连续无错的出餐累积连击、每单额外加分、最高 5 连封顶，这样"又快又稳"有回报
24. 作为玩家，我想在错放时连击清零，这样我知道稳比快更重要
25. 作为玩家，我想让订单难度随时间从 3 小料涨到 5 小料，这样 60 秒有起伏而不是平铺
26. 作为玩家，我想在出餐过渡动画的 0.4 秒里计时暂停，这样换顾客不会偷走我的时间
27. 作为玩家，我想在 60 秒结束时看到结算页——分数、完成订单数、最高连击，这样我知道这局打成什么样
28. 作为玩家，我想在破纪录时看到明确提示，这样成就感是即时的
29. 作为玩家，我想一键重开再来一局，这样我不用退出重进
30. 作为玩家，我想刷新浏览器后最高分还在，这样我的纪录不会白打
31. 作为玩家，我想在手机浏览器上正常玩——没有横向滚动、按钮不被裁掉，这样我不用装 App 就能玩
32. 作为玩家，我想每格配料下面有中文短标签，这样图标画得不够准我也能一眼认出是什么
33. 作为玩家，我想看到文案里有克制的海南味（"食饱未？""够劲！"），这样我会觉得这游戏是懂海南的
34. 作为素材作者，我想在结算页与仓库里看到素材来源与许可，这样署名义务被履行
35. 作为开发者，我想让所有规则都在一个不依赖引擎的纯逻辑核心里，这样改规则不用开编辑器、也不必跑满 60 秒才知道对不对

## Implementation Decisions

**模块划分（三层，规则只住在第一层）**

- **配置层**：配料表（12 格：3 汤底 + 9 小料，各自带 id、显示名、图标、分类）、难度曲线（按已用时切换订单小料数 3 → 4 → 5）、计分规则（基础分系数、连击步长与上限）、文案表。全部是数据，不含逻辑。
- **纯逻辑核心层（唯一被测对象，禁止 import 引擎）**：会话状态机。对外只有三个入口——开局、放入配料、走时间；对外只产出**事件**（放入被接受 / 出餐 / 错放 / 重复被拒 / 难度换档 / 倒计时告警 / 单局结束）与新状态。订单生成、集合匹配、错放判定、连击、计分、计时、难度换档全在这一层判定。
- **Cocos 适配层**：一个组件把输入（拖动落点、点按）翻译成核心调用，把核心产出的事件翻译成表现层调用；它是薄壳，不含任何规则判断。
- **表现层**：订单卡、碗、配料盘、顶栏（倒计时 / 分数 / 连击）、开始页、结算页、背景。只订阅事件渲染，不读核心内部状态。

**架构决定**

- 单向数据流：输入 → 核心 → 事件 → 渲染，不允许表现层反向写状态。
- **状态只存在于核心**：适配层与表现层不缓存规则相关状态（例如"这一单值多少分"必须由核心给出，不能由 UI 自己算）。
- 事件总线用引擎自带的 `EventTarget`，不引第三方状态库或框架。
- **随机数可注入**：订单生成接受一个随机源，生产环境用默认随机，测试注入固定种子——这是让"订单生成"可测的前提。
- 配料池固定 12 格不变，难度只改订单要求的小料数量，不改池子——降低记忆负担，保持"固定时间比分数"的公平。
- 单局只有一个"时间预算"，只在游戏进行相位推进；出餐过渡、结算相位不消耗时间。

**界面与技术约定**

- 竖屏 720×1280 设计分辨率，`FitHeight` 适配；三段式布局：顶部订单区 / 中部碗 / 底部配料盘（12 格）。
- 拖动判定在松手时进行，落区带一定容差，避免小屏边缘难放。
- 最高分用引擎的本地存储（单键：最高分，可附最近一局分数）。
- 中文文案集中在一处，不引多语言；界面字体用系统字体，不内嵌中文字体以控制包体。
- 图标取 MIT 许可的 Fluent Emoji（256×256 PNG），每格图标下配中文短标签；素材来源逐个登记（见 ADR-0001）。
- 背景由用户提供；未到位期间用程序化绘制的黎锦几何纹样占位，不阻塞开发。
- 代码标识符英文，注释与文档中文；领域术语一律以根目录词表为准（汤底 / 小料 / 配料 / 订单 / 碗 / 配料盘 / 出餐 / 错放 / 连击 / 单局 / 最高分）。

**参考文档**：设计基线 `docs/design/mvp-spec.md`；术语 `CONTEXT.md`；素材决策 `docs/adr/0001-asset-sourcing-and-licensing.md`；背景出图需求 `docs/art/background-prompts.md`。

## Testing Decisions

**什么是好测试**：只测**外部行为**——给定一个状态和一次输入，断言产出的**事件**与可观察结果（分数、连击、剩余时间、碗内容、订单是否完成），不测内部实现（不直接断言私有字段、不 mock 内部协作对象、不测事件触发的顺序细节）。测试名用中文描述行为，读起来就是一句需求。

**被测模块**：只有纯逻辑核心层。它是唯一一处"规则集中且不依赖引擎"的地方，也是唯一能用廉价方式覆盖的接缝。适配层与表现层不写自动化测试（拖拽跟手、动画、排版、H5 适配这些只能手动验，见验收清单）。

**先例**：仓库当前**没有任何测试**，本次是第一个——由它建立约定：测试文件放在 `assets/` 之外（引擎不会编译它们），用 vitest，从根目录跑，固定随机种子保证可复现。

**必须覆盖的行为**

- 订单生成：恒为恰好 1 汤底 + 3~5 小料；小料互不重复；全部来自配料池；固定种子下结果可复现
- 集合匹配：放入顺序不同不影响出餐；汤底不匹配不予出餐；多放 / 少放不予出餐
- 错放：扣 3 秒、事件为错放、碗内容不变、连击清零
- 重复放入：碗中已有同一配料时再次放入被静默拒绝、**不扣时间**、不产生错放事件
- 出餐：凑齐即触发一次且只触发一次；出餐后碗清空、换新订单、连击递增
- 计分：每单基础分 = 10 ×（小料数 + 1）；连击每单额外 +5、上限 +25；错放后连击重置、加分回落
- 难度换档：已用时间越过 20 秒 / 40 秒时订单小料数变为 4 / 5，且换档只发生一次
- 计时：只有进行相位消耗时间；过渡与结算相位不消耗；时间归零触发单局结束且不再接受放入
- 单局结束：结束后再次放入配料不产生任何事件、不改变分数

**开发期自检（不是测试，是验证通道）**：`assets/scripts/debug/SelfCheck.ts` 在预览启动后脚本化地打一局，把能脚本化的表现层行为自动跑一遍，结论打到控制台。它不替代下面这些手动验收项——Game View 的内容区截不到图，这是当前唯一可靠的运行期验证通道。12 号切片（上线构建）前连同整个 `debug/` 目录一起删掉。

**手动验收**（自动化覆盖不到的部分）见设计基线里那 10 条清单，尤其第 10 条需真机点一次。

## Out of Scope

- 音频（BGM 与音效一律不做，等玩法定型后再单独起 spec）
- 关卡 / 波次 / 无尽模式等单局之外的内容结构
- 联网排行榜、账号、云存档
- 多语言与本地化
- 定制美术贴图（emoji 图标升级为定制贴图属于后续独立工作）
- 顾客骨骼动画、粒子特效等表现层升级
- 真机自动化测试、性能压测、兼容性矩阵测试

## Further Notes

- **开放项（不阻塞）**：背景图待用户交付；期间程序化黎锦纹样占位。交付后只需替换图集与背景池，不影响任何规则代码——这是把背景做成"纯表现"的直接好处。
- **已知妥协**：12 格里约 6 格没有直接对应的开源图标（椰奶 / 红糖水 / 红豆 / 绿豆 / 西米 / 通心粉），靠近似图标加中文短标签保证可辨。这是"先跑通玩法、后升级美术"的自觉取舍，不是疏漏。
- **文化准确性提醒**：背景与文案里出现的黎锦纹样只用有文献明确的三类（人形纹、菱形格二方连续、水波纹），骑楼元素只用确证过的（连续柱廊、雕花阳台、彩色窗楣、灰塑、女儿墙、民国式街灯）。没有确证的元素不写，宁可少画。
