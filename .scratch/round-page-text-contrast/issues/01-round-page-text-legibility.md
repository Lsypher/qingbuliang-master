# 01: 单局页压在随机背景图上的文字看不清

Status: done

**What to build:** 单局页有 6 处文字直接压在每局随机抽出的背景图上、自己没有底板，底色一亮就读不清。要让它们在任意一张背景上都读得清，并且描边必须是**字形描边**，不能用两层偏移文字。

**问题（用户报，4 张截图见 `evidence/01-before-no-outline-1..4.png`）**

圈出的 6 处是：顶部倒计时数字、分数 / 完成订单 / 连击统计行、订单卡标题「顾客要这一碗」、已放进度「已放 0/4」、碗区标题「碗中」、空碗提示。四张截图来自不同的单局背景，问题在亮底（沙滩、木墙、晴空）上最刺眼。

**已定（用户确认）：**

1. 描边必须是**字形描边**。第一版按"暗色垫底略偏移 + 亮色正文"叠了两层标签实现（`evidence/02-offset-shadow-rejected.png`），被用户否掉，原话是*"看起来像两行文字重叠，视觉晕眩"*。
2. 描边样式对齐开始页"最高分"节点：`enableOutline` + `outlineColor (74,44,20)` + `outlineWidth 3`。
3. 字体色重新搭配，要给出审美 / 色彩科学依据。
4. **不加半透明底板、不恢复整屏压暗**：沿用 `UI_COLOR.backgroundDim` 注释里那条既定取舍（"不再整屏压暗，改由各元素自带底衬托住自己"）。
5. 本票是一处修复，**不写 `spec.md`**——它不是新特性。

**Blocked by:** 无

### 取舍记录

1. **为什么是描边而不是半透明底板**：底板会盖住美术，且与既定的"各元素自带底衬托住自己"取舍相冲（那条决定了整屏压暗层的 alpha 为 0）。字形描边不遮美术、随字号缩放自动跟随。
2. **为什么正文一律走暖色系**：背景美术通篇暖色（木纹、沙滩、夜市灯）加大片亮青。冷灰压上去既显脏又争不到对比；换成与背景同族的米黄后，层级只靠明度与字号区分，整体更统一。
3. **一个反直觉的实测数据**：暖米黄对**亮青天空**只有约 **0.95:1**——正文色本身在亮背景上几乎隐形，**可读性其实全由描边承担**（米黄对描边约 9:1）。所以描边必须够实，这也是叠影方案撑不住、真描边撑得住的原因。
4. **告警红的上限**：告警红 `(255,74,74)` 是中明度，配任何描边都拉不开大对比——配近黑的红 `(30,4,4)` 已到约 5.9:1，接近这套配色的上限。再想高就得把红提亮，那就不像告警了，故停在 5.9:1。
5. **为什么反馈飘字不共用 `textOutline`**：红字配棕边会发浑。错放 / 得分 / 连击 / 打勾各自配与自身正文同色系的深色描边（那四支是改动前就有的，本次只改了名字与注释措辞）。
6. **描边宽度按字号等比而非固定 3**（**实现者的判断，未获用户逐字确认**）：用户要的是"类似最高分那种描边样式"，而最高分是 34 号字配固定 3。固定 3 压在 24 号字上笔画会明显发胖，故改成 `fontSize × 0.09`（下限 2），34 号仍落在 3。代价是统计行、已放进度这些**用户圈出的最小字**实得 2——而恰恰是它们最依赖描边（见上一条 0.95:1）。若眼验觉得偏淡，把 `outlineWidthFor` 改成固定返回 3 即可（一行改动）。
