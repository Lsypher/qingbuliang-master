# 开始页的静态骨架放在场景里，其余页维持现状

**决定**：开始页的静态骨架作为节点摆在 `assets/scenes/main.scene` 里——标题（艺术字或兜底文字）、副标题与其圆角底框、玩法说明、最高分行、开摊按钮，位置与尺寸都在编辑器里调、所见即所得。单局页与结算页的装配方式**一行不动**，维持现状。

**为什么**：愿意动场景的唯一动机是"开始页要反复调版面"。这次升级的重点就是把这一屏从代码拼装的调试页变成有设计感的封面，之后还要反复试间距与层级；骨架进了场景，改一次间距就不必再跑一次预览。

**为什么不顺手把另外两页也迁进来**：单局页是动态布局（拖拽跟手、随机图标、计时重排），它的节点内容本来就由各视图组件在运行时装配，迁进场景收益低，而"踩坏已经跑通的自适应逻辑"的风险高；结算页是纯展示页，骨架已经在场景里、也没有反复调版面的需求，不必动。这条不一致是自觉取舍，不是遗留疏忽。

## Considered Options

- **只把开始页的静态骨架放进场景**：选中。调版面最频繁的一页拿到所见即所得，其余两页零风险。
- **三页的静态部分全放进场景**：一致，但单局页的动态内容（订单卡图标行、碗中图标、拖动幽灵、进度条填充）无论如何都得运行时装配，最后仍是混合形态；代价是要重写一遍已经验收过的自适应逻辑。
- **全部维持运行时装配**：最一致，但开始页每改一次间距就要跑一次预览，与本次升级的动机直接冲突。

## Consequences

- `assets/scenes/main.scene` 开始承载开始页的版面：标题艺术字、副标题底框、最高分行、按钮底图都是场景节点，容器位置由编辑器调。
- 场景里的文字仍是"摆版预览值"：页面每次显示都由视图组件从 `config/strings.ts` 重刷一遍，文案表依旧是唯一文案来源。
- 编辑器保存场景时会按当前 Game View 画幅回写 Canvas 的自动布局值（位置与内容尺寸）。每次保存后都要检查 diff，别把这类噪音夹进提交。
- 表现层因此是混合形态：有的界面在场景里摆，有的在代码里装。新增界面组件时写清自己属于哪半边——`StartView` / `ResultView` 只改场景骨架上的文字，`HudView` / `OrderCard` / `BowlView` / `IngredientTray` / `GuideHint` 自己装配节点——避免后来者把场景里那份当成遗漏。
- 三页仍在同一场景里用 `active` 互斥切换；切页广播与背景层的响应方式都不变。
