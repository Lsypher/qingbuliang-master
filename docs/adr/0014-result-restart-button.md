# 结算页"再来一碗"按钮补上绿胶囊底板

**决定**：结算页的重启按钮从"一行米黄描边文字"改成**底板 + 文字两层**，四处改动：

1. **底板图**：`assets/resources/art/ui/restart-button.png`（用户交付的 `再来一碗.png`，**3296×1184**，**亮绿胶囊，图上没有字**）。结构：`RestartButton`（Button + 一个空的 Graphics）→ `Board`（Sprite 底板）+ `Label`（"再来一碗"，来自 `config/strings.ts`）。结构、绘制顺序与导入 / 场景上的硬约束见 ADR-0013 的「结算页底板的导入与场景约定」一节（那里是唯一权威说明）。
2. **尺寸**：按钮与底板都是 **267.2×96**——高度沿用原按钮的 96，宽度按素材比例 3296:1184 等比算（见下"为什么"）。
3. **文字**：**白字 + 深绿近黑描边（`#1B3A0E`，宽 4）+ 加粗**；字号 40、行高 52 不变。原底色是 `textBody` 暖米黄、描边是 `textOutline` 深暖棕。
4. **按下反馈**：Button 的过渡方式由 NONE(0) 改成 **SCALE + 0.95**（`zoomScale` 同时由默认的 1.2 改小）。

**为什么**：

- **素材无字 → 文字仍由引擎渲染**：与结算页标题同一条（见 ADR-0013）。按钮文案继续归 `strings.ts`，改文案不用重出图，这与开始页那张"自带开始游戏"的按钮底图（ADR-0011）刚好相反。
- **必须拆成两个节点**：`Sprite` 与 `Graphics` 都是 `UIRenderer` 的派生组件，**引擎不允许挂在同一个节点上**（在编辑器里给这个按钮加 Sprite 会被直接拒绝：`conflicts with the existing 'cc.Graphics' derived component`）。所以底板只能当子节点，靠**兄弟顺序**（Board 在 Label 之前）保证它画在文字之下——ADR-0013 选拆节点是为了"顺序可见可查"，这里则是**没有第二条路**。
- **原来的按钮连底板都没有**：这个按钮此前只靠一行字撑场面（`Graphics` 是个 `_impl` 缺失的空组件，什么也不画；结算页的整屏压暗层更是 alpha 0），所以那张绿胶囊是**补上一直缺的底**，不是替换旧底。
- **尺寸按高度缩、宽度等比**：素材比例 2.784:1，原按钮是 320×96（3.333:1）——直接套 320 会把胶囊横向压扁约 17%、圆角变椭圆。取高度 96 不变、宽按等比得 **267.2**，按钮高度与版面位置一行未动，只有宽度收窄；而 267.2 与标题木牌的 267.8 几乎同宽，这一页的上下两块因此对在同一条中轴上。
- **白字 + 深绿描边**：白字是这套界面里"按钮 / 标题"的既有字色（开摊按钮图上那四个"开始游戏"就是白字配深棕描边，结算页标题也是白字）。白字压在亮绿上只有约 1.8:1，可读性全靠那圈描边把字形抠出来；描边取**按钮深绿边缘的同族色**，而不是 `textOutline` 的深暖棕——暖棕边压在冷绿底上会发浑。
- **按下反馈用缩放而不是换图**：素材只有一张（没有按下态），缩放是唯一"零素材成本"的正反馈；Button 的 SCALE 过渡一行数据就能配好，不必像开始页那样自己接触摸事件（那里之所以自己接，是因为换图已经占用了 Button 唯一的过渡槽）。

## 代价与边界

- **没有独立的按下态图**：按下只缩到 0.95。要做出"压暗 / 凹陷"的按下态，得再出一张图并把 Button 的过渡换回 SPRITE（那时缩放就得像 `StartView` 那样自己接）。
- **按钮比原来窄了约 16%**（320 → 267.2）：仍是这一页最宽的一块实心底色，位置与高度都没动。
- **素材体积**：3296×1184（3.4 MB）在屏上只显示 267.2×96，约 12 倍冗余。要压体积，出一张 **534×192** 覆盖同名文件即可，代码与场景都不用改。
- **缺图不阻塞**：底板取不到时 `Board` 不渲染，这一处只剩那行带描边的白字——与标题底板、最高分奖杯是同一条兜底原则。
- **那个空的 `Graphics` 组件**：本次**没动**它（它不画任何东西，删与留都不影响观感）。想清理的话属于另一件事——它会同时改动结算页骨架的组件构成，测试里锁的是子节点与 Sprite，不受影响。
- **导入设置、`sizeMode`、节点层这三条硬约束**见 ADR-0013 的「结算页底板的导入与场景约定」一节。

## Considered Options

- **补绿灯胶囊底板 + 白字深绿描边（选中）**：素材怎么给就怎么用，文字仍归文案表管。
- **把"再来一碗"烤进胶囊**（ADR-0011 的做法）：素材里胶囊是空的，字得美术再画；此后改文案=重出图。
- **保持 320×96、把素材横向拉伸**：胶囊被压扁、圆角变椭圆，排除。
- **在 `RestartButton` 节点上直接挂 Sprite**：引擎不允许（与 Graphics 互斥），排除。
- **沿用按钮原来的 NONE 过渡**：点下去一点反应都没有，补了底板之后这种"死按钮"感更明显。
- **白字改深绿字**：对比度更高（约 6.7:1），但与开摊按钮、结算页标题的白字不再统一；本次按既有美术语言选白字 + 描边。

## Consequences

- `uiFactory.UI_COLOR` 新增 `restartButtonOutline`（深绿近黑）；`textOutline` 的共用面再收一处（结算页从 6 处变 5 处）。
- `ResultView` 把原先只服务标题的装帧逻辑抽成 `attachBoardArt(host, boardName, path, what)`，标题与按钮共用一份（两份写法迟早会漂移）。
- `tests/resultPageSkeleton.test.ts` 补上这一处的断言：`RestartButton` 的子节点是 `Board` + `Label` 且**顺序如此**、`Board` 挂 `Sprite`（CUSTOM、帧指向 `restart-button.png`）、尺寸宽高比等于素材比例、文字是白字 + 描边开启 + 加粗 + 深绿描边。
- `CREDITS.md` 与 `docs/art/ui-prompts.md` 登记这张图与它的出图需求（规格、比例、导出尺寸、命名）。
- 结算页的界面图由 1 张变 2 张，命名保持 `<用途>-<部件>.png`（`result-title-board` / `restart-button`）。
