# 结算页标题加木牌底板，文字改白字黑边（底板无字）

**决定**：结算页标题"食饱未？"从**一个文字节点**改成**两层**：`Title`（容器）→ `Board`（木牌底板图）+ `Label`（文字）。随之四处改动：

1. **文字样式**：白色（`#FFFFFF`）+ 暖近黑描边（`#24160C`，宽 5）+ 加粗，字号 **64 → 50**、行高 63；背景色（原暖金 `textAccent`）不再使用。
2. **底板图**：`assets/resources/art/ui/result-title-board.png`（用户交付的 `食饱未.png`，**3360×1312**，图上**只有木牌、没有字**）。场景里的 `Title/Board` **直接引用了这张图的帧**（编辑器里所见即所得），`ResultView` 另留一份按文件名加载（`art/ui/result-title-board`）作兜底——与开摊按钮、奖杯那两处同一个形状。
3. **尺寸**：`Title` 与 `Board` 都是 **267.8×104.58**——这是按素材比例 3360:1312 与原高 104.58 等换算出来的等比宽（详见"为什么"）。
4. **绘制顺序**：`Board` 排在 `Label` 之前（兄弟节点顺序即绘制顺序），底板才在文字之下。

**为什么**：

- **文字仍由引擎渲染**：这张素材是**无字底牌**，与 ADR-0011 那张"自带开始游戏四个字"的开摊按钮底图刚好相反。所以这里**不能**停用文字节点——底板只是背景，"食饱未？"照旧来自 `config/strings.ts`（改文案只改文案表）。
- **为什么拆成两个兄弟节点、而不是在 `Title` 上叠 Sprite + Label 两个渲染组件**：同节点上多个渲染组件的先后在编辑器里既看不见也调不动，一旦排错就是"底板盖住文字"这种肉眼易漏、代码里也查不出的错；兄弟节点的**先后就是绘制先后**，写在同一份场景数据里，还能被测试断言。这条是本次唯一的结构性改动。
- **底板图既在场景里接线、也留一份代码兜底**：接线是为了编辑器里直接看得到成品（摆版与验收都靠它），而且它与"同名覆盖即换图"**不冲突**——同路径覆盖文件时 `uuid` 不变，换图照样生效；只有"删掉再重新导入"才会换 `uuid`，那时得回编辑器重接一次（`tests/resultPageSkeleton.test.ts` 里那条 uuid 断言会先报错提醒）。代码里那份按文件名加载与开摊按钮、奖杯同形，管的是"帧被清空 / 图还没导进来"这一种情形。
- **尺寸按原图比例算、不做横向压缩**：素材是 3360×1312（2.56098:1），原来那个文字节点是 256×104.58（2.448:1）。若沿用 256 宽，木牌会被横向压缩约 4.5%；ADR-0011 已经为"宁可改尺寸也不让交付图变形"定过调子，这里照办，取 104.58 高对应的等比宽 **267.8**。
- **字号 50 是反推出来的**：**交付的底板上没有字**，参照的是用户附的那张效果图（白字 + 深色描边压在木牌上）——图里"食饱未？"四个字约占板面可见宽的七成。按同一占比缩到 267.8 宽后，换算成 Cocos 的字号约为 50（汉字宽 ≈ 字号），故由 64 降到 50。描边宽 5 沿用 `uiFactory.outlineWidthFor` 的规则（字号 × 0.09 取整）。

## 结算页底板的导入与场景约定（权威落点）

结算页两块底板——本条的标题木牌与 ADR-0014 的"再来一碗"胶囊——共用同一套约束。
**这一节是它们的唯一权威说明**：ADR-0014、`CREDITS.md`、`tests/resultPageSkeleton.test.ts` 与代码注释只引用本节，不复述理由。

| 约定 | 取值 | 为什么 |
| --- | --- | --- |
| 导入 · 裁剪 | `trimType: none` | 保留原始画布，四角圆角的位置才与设计稿对得上 |
| 导入 · 自动图集 | `packable: false` | 透明底裁切件不进图集，避免边缘渗色 |
| 导入 · 九宫格 | 边距全 0 | 两块底板都是整图等比拉伸，不是"可拉伸中段"的构造 |
| 场景 · 尺寸模式 | `Sprite.sizeMode = CUSTOM` | 交付图有 3360 / 3296 像素宽，留成默认的 TRIMMED 会在贴帧那一刻把节点撑到原图尺寸、糊满整屏 |
| 场景 · 节点层 | `Board` 与 `Label` 的 `layer = UI_2D`（33554432） | 程序化新建的节点默认落在 `DEFAULT`（1073741824），而画布相机只看 UI_2D——忘了改就是"数据全对、画面全空" |
| 场景 · 绘制顺序 | `Board` 排在 `Label` 之前 | 兄弟顺序就是绘制顺序，反了底板会压住文字 |
| 加载 | 场景里接线 + `ResultView` 按文件名兜底 | 接线让编辑器所见即所得；同名覆盖文件时 `uuid` 不变，换图照样生效。兜底管的是"帧被清空 / 图还没导进来" |
| 命名 | `<用途>-<部件>.png`（`result-title-board` / `restart-button`） | 素材登记、代码常量与注释都按这个名字指代同一张图 |

场景那四条与命名都由 `tests/resultPageSkeleton.test.ts` 锁着；导入设置那三条读不出场景，靠交付时按 `CREDITS.md` 的登记表手工核对。

## 代价与边界

- **白字压浅黄木牌，可读性全在描边和加粗上**：若日后换个更浅或更花的底板，先量对比度再定字色。
- **"圆润"只是近似**：文字用系统字体（`Arial` + `isBold`），"粗壮"由加粗承担，"圆润"到不了图上那种圆体笔画。要像素级一致，得引入一份**授权明确**的圆体字体文件（SIL OFL 之类）并登记许可——本次没有自带字体，故不做（`docs/adr/0001-asset-sourcing-and-licensing.md` 的取材原则）。
- **素材体积与显示尺寸差 12 倍**：3360×1312（2.4 MB）按原图入库，屏幕上只显示 267.8×104.58。这与奖杯（2048² 显示 44²）是同一批交付习惯；要压体积，重出一张 536×210 的图**同名覆盖**即可，代码不用动。
- **缺图不阻塞**：底板加载失败时 `Board` 没有帧、自然不渲染，这一页只显示那行带描边的白字——与"奖杯缺失时最高分那行只显示文字"是同一条兜底原则。
- **导入设置、`sizeMode`、节点层这三条硬约束**（改错分别是变形、糊屏、整个不渲染）见上面「结算页底板的导入与场景约定」一节——那里是唯一权威说明，这里不再复述。
- **结算页其余几处文字不受影响**：它们仍是"暖金 / 米黄 + 深暖棕边"（`uiFactory.UI_COLOR` 的 `textAccent` / `textBody` / `textOutline`），标题专用的描边色单列一支 `resultTitleOutline`。
## Considered Options

- **加底板 + 白字黑边（选中）**：完全按下发的素材呈现，文字仍归文案表管，改动只在结算页。
- **把字烤进底板、停用文字节点**（ADR-0011 的做法）：素材里木牌是空的，字得美术再画一遍；而且从此改标题=重出图，比现在这条路贵。
- **在 `Title` 上同时挂 Sprite 与 Label**：少一个节点，但绘制先后不可见、不可调，排除。
- **沿用 256 宽**：省一次改尺寸，代价是交付图被横向压 4.5%，排除。
- **底板走九宫格**：木牌四角装饰随节点尺寸等比缩放更稳，但这张图的圆角与木纹本来就不是"可拉伸中段"的构造，直接整图等比拉伸已是正确做法，没必要加一层切边。
- **只改文字样式、不加底板**：就是当前状态，与交付的设计稿（白字黑边 + 木牌）不符。

## Consequences

- `uiFactory.UI_COLOR` 新增 `resultTitleOutline`（暖近黑，`#24160C`），并订正 `textAccent` / `textOutline` 的说明（标题不再用暖金，共用 `textOutline` 的结算页文字从 7 处变 6 处）。
- `ResultView` 多一件运行时职责：兜底按文件名取底板图贴上 `Title/Board`（场景已接线时不会触发）；文字改写到 `Title/Label` 上（`setLabelText(this.node, 'Title', …)` 换成对子节点的写入）。
- `tests/resultPageSkeleton.test.ts` 锁住这一页的骨架：`Title` 只有 `Board` + `Label` 两个子节点且**顺序如此**、`Board` 挂 `Sprite`（`sizeMode` 为 CUSTOM、帧指向 `result-title-board.png`）、`Label` 的样式取值（白字 / 描边开启 / 加粗 / 字号 50）。
- `CREDITS.md` 与 `docs/art/ui-prompts.md` 新增这张图的登记与出图需求（规格、导出尺寸、留白与命名）。
- 底板图是**结算页第一张**界面图；日后这一页再出图（如"再来一碗"按钮）沿用同一套命名与加载约定。
