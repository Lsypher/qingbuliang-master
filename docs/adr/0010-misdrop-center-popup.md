# 错放的"-3 秒"再加一张中央图片弹窗，位置落在碗内上部空档

**决定**：错放时除既有的边缘红闪、顶部"-3 秒"飘字与配料弹回之外，再在单局页 `(0, 140)` 弹出一张图片（`assets/resources/art/ui/misdrop-penalty.png`，抖动 + 两侧残影，约 0.9 秒后自动淡出并销毁），实现收在 `ui/misdropPopup.ts`；这张图在准备过场期间与另两项预载一起加载。

**为什么位置不是屏幕正中**：`(0, 0)` 恰好是碗的"空碗"提示与碗内图标行所在处——碗区中心在 `-25`，"空碗"/图标行在碗区局部 `+10`，即单局页 `-15`。放正中必然压住其中一样。`140` 是**唯一不压静态文字**的落点：碗内 64 像素图标行上沿约 `+17`，再往上就是订单卡。

**代价：这一带与出餐类浮层纵向重叠，躲不开**。得分飘字锚在碗心 `+120`（≈95），连击喊话在 `+250`（≈225），而弹窗高约 140——碗上方没有任何一段能容下这条横带而不与其中一条相交。所以"不覆盖页面其他文字"**只兑现了一半**：静态文字（空碗、已放进度、订单标题）没被压，出餐浮层会叠。重叠窗口很窄（得分飘字 0.7 秒、喊话约 1.1 秒，要"出餐后不到一秒就错放"才撞上），不值得为它把弹窗挤出这片空档。这条以**已知偏差**记录，不假装已解决。

**为什么"-3 秒"保留两处**：顶部飘字锚在倒计时右侧（见 ADR-0009），语义是"扣的是时间"；中央弹窗管"一眼看见"。两者共用同一条 `Misdrop` 事件，同时出现、同时不发生，不存在只出一个的中间态。

**为什么图走"过场预载"而不是首次错放现拉**：错放反馈要求"触发即显示"，而 `resources.load` 是异步的，首次错放现拉会晚一两帧才冒出来。过场本来就是一段加载窗口（见 ADR-0003 与 `game/GameLauncher.ts`），把这张图并进那批预载任务不新增任何机制。

**弹入缩放是需求的推论**：需求要"醒目且不显突兀"，一张图硬生生跳出来正属于"突兀"。0.12 秒从小弹到位、同时淡入，短到不构成延迟。

## Considered Options

- **放进屏幕正中 `(0, 0)`**：最"中央"，但必然压住"空碗"或碗内图标，被否。
- **继续用 `createOutlinedText` 画这段字（不新增素材）**：与既有飘字同一套、也免掉"扣时值烤在图里"这个坑；但用户要的就是这张带红底与时钟图标的现成美术件，观感与代码描边字不是一回事。
- **替换掉顶部飘字、只留中央弹窗**：信息不重复、画面更干净；代价是丢掉"扣在倒计时上"这层指向，且要改动 ADR-0009 定下的锚点契约。本次选择两处并存。
- **为避开出餐浮层再挪位置或缩小弹窗**：按坐标带量过，碗上方没有能容下它的空档；缩到能避开就得小到失去"一眼看见"的作用。
- **抖动用随机数**：改用手写的一条确定性序列，观感可复现，也便于"改了有没有效果"一眼比对。
- **按 `frame.width / frame.height` 算图片比例**（第一版这么写，被实机截图打回）：引擎里 `SpriteFrame.width` 的实现是 `return this._texture.width`，量的是**纹理**、不是图片内容。**改为按 `frame.rect`**（与内容绑定的裁剪矩形），见 `ui/misdropPopup.ts` 的 `popupHeightRatio`。

## Consequences

- **"-3"这个数字散落在三处**（常量、`STRINGS.misdropText`、位图），彼此没有代码绑定——这是选用现成美术件换来的代价。权威说明只保留一处：`config/balance.ts` 的 `MISDROP_PENALTY_MS` 注释，其余各处只放指针。改扣时值 = 改常量 + 改文案 + 重出图。
- `ui/misdropPopup.ts` 与 `ui/ingredientIcon.ts` 的"帧缓存 + 已决标记 + 预载任务"已收成 `uiFactory.createSpriteFrameSlot` 一份；缺图时只跳过弹窗，不阻塞进局、不报错中断。
- **与出餐浮层纵向重叠**：见上，以已知偏差记录，不做避让。
- 弹窗只挂 Sprite / UIOpacity，不吃触摸，错放后可以立刻继续拖拽。
- **人工验收**：错放时屏幕中央偏上弹出一张"-3 秒"图，**形状与素材一致（横向的红底条，不是正方形）**、抖动并带两侧残影，约 0.9 秒后消失；顶部倒计时右侧的"-3 秒"飘字照旧；期间拖拽配料不受影响。
  **这条尚未实机确认。** 比例异常那次的修复是按"内容矩形"取比例（语义正确，且对纹理尺寸变动免疫），但**没取到运行时的实测数据**：改代码后预览无法重载，本版编辑器不存在 `preview.stop/play/reload` 三个消息，所以只能在编辑器场景里核对引擎行为（`CUSTOM` 不覆盖 contentSize、`trim` 为 true 时绘制区域等于 contentSize、`trimmed` 下引擎按 `rect` 设尺寸）。现象与修复之间的因果链还有一段没合上：实机截图量出弹窗红底比例约 1.08，而素材红底是 2.03，方向上确实是"高度被拉长"；但按代码算出的 contentSize 应约 240×140，与实测不符，**差在哪里尚未定位**。下一次动这块时，优先补上运行时那次实测。
