# 点按与拖动的判定收进一个不 import 引擎的手势状态机，配料盘不再挂 Button

**决定**：新增 `assets/scripts/ui/dragGesture.ts`，`createDragGesture()` 持有"一次触点落下到抬起"之间的全部判定——起点、阈值、一次只认一根手指、抬手给出落点，**不 import 引擎**；配料盘只负责跟手幽灵的建与拆，以及把状态机给出的结论翻译成总线事件。

**连带取消配料盘格子上的 `Button`**。改动前：点按走 Button 的 `CLICK`，拖动走节点自己的 `TOUCH_*`，而两者会同时到达——手指按在格子上、拖动之后松手，Button 也照样发一次 `CLICK`，代码必须把它拦掉。拦法依赖一条**没有文档背书**的顺序（`addComponent(Button)` 先注册监听，所以 `CLICK` 总在本组件的 `TOUCH_END` 之前触发）。现在"一次手势只由状态机解释"：没越过阈值就是点按、越过了就是拖动结束，两条路都在 `TOUCH_END` / `TOUCH_CANCEL` 里判完。

**为什么**：这条规则里全是带判断的分支——阈值是**严格大于**、比较的是**距起点的直线距离**（不是逐帧位移，所以来回抖动不累积越界）、越过之后**不回落**（否则拖出去再拖回来会在半路变回点按，抬手时配料直接进碗）、多指只认第一个触点、拖出格子后松手派的是 `CANCEL` 而不是 `END`。它们此前全长在 Cocos 的回调里，只能靠手动拖一遍。

## Considered Options

- **两类手势都交给状态机判、取消 Button（选中）**：一次手势只有一个解释者，那条时序依赖连同 12 个 `Button` 一起消失。代价是输入路径变了一次，需要验收"点按仍能放配料"。
- **保留 Button，只把"这次手势算不算拖动"抽出来**：改动最小，但那条时序依赖留着，且点按与拖动仍是两条互不知道的路径。
- **保留 Button，把 `moved` 变成显式查询**：把隐式依赖变成显式依赖——仍然是依赖。

## Consequences

- 配料盘每格不再挂 `Button`（少 12 个组件），点按事件改由 `TOUCH_END` 判定后发 `DropIngredient`。
- `DRAG_THRESHOLD_PX` 从配料盘搬进状态机（"常量跟模块走"，与 ADR-0005 同一条规则），判定用严格大于。
- 跟手幽灵仍在**触点落下那一刻**就建（点按也会建一份、同一帧拆掉）：这次只抽判定，不碰观感。
- 状态机只交结论，不碰节点；幽灵的建拆留在配料盘。
- **人工验收**：点按仍能把配料放进碗、拖到碗上松手仍能放入、拖拽跟手不变（点按失效是响亮的失败，不会静默）。
