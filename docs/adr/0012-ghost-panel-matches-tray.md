# 配料幽灵的底板改用配料盘格子那套色

**决定**：`assets/scripts/ui/ingredientGhost.ts` 的面板配色整体换掉，四处一起改：

1. 底板：`UI_COLOR.panel`（深蓝近黑 24/32/46、α235、**直角**）→ `UI_COLOR.traySlot`（近白 242/249/240、不透明）；绘制从 `paintPanel` 换成 `paintRoundPanel`，圆角 13（与格子同一个比例：高度的两成）。
2. 中文名：`UI_COLOR.textPrimary`（纯白）→ `UI_COLOR.traySlotLabel`（深暖灰）。
3. 跟手描边：`UI_COLOR.textAccent`（暖金）→ `UI_COLOR.traySlotLabelBase`（深暖棕）。
4. 弹回描边不变，仍是 `UI_COLOR.misdropText`（错放红）。

`UI_COLOR.panel` 的唯一使用处就是这里，随之删除；`transitionBackdrop`（准备过场整屏底）仍取同一个深蓝近黑，只是不再声称"与面板同色系"。

**为什么**：深蓝近黑的**直角**矩形是单局页上唯一一块近黑，压在明亮的碗与木桌上像一块没做完的占位块，与整屏暖色（木纹、沙滩、近白格子）不搭——而且玩家在拖动与按住不放时都会看到它（幽灵在 `TOUCH_START` 就建，松手才拆）。

底板本身不能删：它是跟手幽灵与弹回幽灵的共同形态，同时承载两件不能丢的职责——把透明底图标与中文名从任意背景上托起来（可读性），以及承载描边色这条**唯一的**差异通道（见 ADR-0008）。删掉底板等于连描边一起删，两个幽灵会变得完全一样。

## 为什么必须成套改，不能只换一个色值

只把底板换成近白，会立刻撞上两条已经写在配色表里的约束：

- **白字会消失**：`textPrimary` 压在 `traySlot` 上只有约 1.07:1，中文名等于没有。
- **暖金描边会糊没**：`textAccent` 压在浅底上不可辨——这条教训在 `traySlotLabelBase` 的注释里已经记过一次（配料盘的汤底标签从暖金换成深暖棕，就是因为这个）。

所以底色、字色、描边色是一组关系，不是三个可以各改各的值。改完后的对比度：深暖灰字 ≈ 8.5:1、深暖棕描边 ≈ 5.5:1、错放红描边 ≈ 3.3:1。

## 代价与边界

- **幽灵与格子同底同色系后，区分度只剩"小一号（120×64 对 160×96）+ 跟随手指 + 一圈描边"**。这是有意的取舍：与整屏一致优先于"幽灵必须自成一格"。
- **弹回的红边比原先弱**：压在近白底上约 3.3:1，压在原来的深蓝近黑上则高得多。仍达图形元素 3:1 的门槛，且红色的语义没变。
- **底板不透明**（沿用 `traySlot` 的 α255）：幽灵是浮层，底下是什么都不该影响图标与名字的可读性。
- **四处配色都在运行时装配**，不进场景；改主题仍只改 `uiFactory.ts`。

## Considered Options

- **直接移除底板**：白字与描边一并没有，"跟手 / 弹回"的区分通道也一起丢（ADR-0008 的立意）；拖到碗上时幽灵图标还会与碗里已有图标糊在一起。不选。
- **保留深色板，只降不透明度或改圆角**：不解决"整屏唯一一块近黑"这件事；透明度降下去反而让白字重新压到背景上。不选。
- **给幽灵另定一支近白底常量**：会与 `traySlot` 重复定义同一个色值，两处迟早漂移，而"与配料盘一致"恰恰是这次要保证的事。所以共用同一支。

## Consequences

- **ADR-0008 的 Considered Options 里"跟手用强调色表示'拿着东西'"这一句被本条取代**；该条"描边色是唯一的差异通道"仍然有效，只是跟手那支换成了近白底上的深暖棕。
- `UI_COLOR` 少一支（`panel`）；`textPrimary` 只剩准备过场文案一处在用（另有 `createLabel` 不传色时的默认值仍是它）；`textAccent` 只剩倒计时数字一处（开始页与结算页那几处烤在场景里，读的是本表的取值、改本表不会跟着变）。
- 日后若出现第三种幽灵，仍按 ADR-0008 的约定给 `ingredientGhost.ts` 加出口，描边色从"近白底上压得住的深色"里挑。
