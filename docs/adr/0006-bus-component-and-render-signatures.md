# 订阅生命周期收进一个组件基类，渲染签名单独成模块

**决定**：新增 `assets/scripts/game/busComponent.ts` 的 `BusComponent`。订阅事件总线的组件一律继承它：**登记与注销由基类接管**（原先 26 行 `bus.on`/`bus.off` 配对收敛成基类里的 2 行），生命周期也由它接管——**子类不再写 `onLoad` / `onDestroy`**，改用 `onViewLoad` / `onViewDestroy`（JS 里子类覆写后基类那份就不再执行，没有自动串链，所以换名字是唯一能保证基类代码一定跑到的方式）。9 个文件随之迁移：8 个视图 + `GameSession`。

**顺带把"什么算需要重绘"抽出来**：`BowlView` / `OrderCard` / `HudView` 三处手拼的签名字符串收进 `assets/scripts/ui/renderSignatures.ts`——不 import 引擎，因此进 vitest。签名漏掉一个会影响显示的字段，症状是**界面不刷新**：不报错、不崩，只是画面对不上，而这类错此前一条断言都没有。

**为什么值得为一个基类动 9 个文件**：那 26 行不是"重复得不好看"，而是**漏写一次就是跨局的幽灵订阅**——组件销毁后仍收到 `Render`，转头去碰已经回收的节点。这类错的现场离原因很远（表现为切页后的偶发崩溃），而它现在在结构上不可能发生：注销只有一处。

**为什么签名守卫不进基类**（这条容易被后来者重新提出来，故写明）：把"值没变就不重绘"放进基类看着更省，但它会让签名没变时整个渲染回调都不执行，于是这个守卫会被当成"事件投递的门"——将来任何视图想在渲染载荷里接核心事件（`GuideHint` 接 `served`、`ServeFeedback` 接 `served` 就是这种用法），都会被静默吃掉，而症状是"事件没反应"而不是"没重绘"。守卫留在调用点，是一行看得见的判断。

## Considered Options

- **通用订阅 + Render 钩子（选中）**：`listen(event, handler)` 覆盖任意事件，`onRendered` 覆盖最忙的那条并自动订阅（不覆写就不订阅，适配层与背景层因此每帧不多收一次调用）。
- **只管 Render 这一类**：接口类型更紧，但 26 行里有一半听的不是 `Render`（输入事件、切页、错放），砍掉一半等于留下"两种写法并存"这个更差的状态。
- **再抽一层不 import 引擎的"订阅簿"**：簿记只有一个消费者，按"一个适配器是假设的接缝，两个才是真接缝"属于自娱自乐；等它长出分支（如按页面启停订阅）再回头看。
- **守卫进基类**：见上，会把重绘短路误做成事件闸门。
- **只迁带签名守卫的三个视图**：半迁移状态对新来者最贵，还得判断某个视图属于哪一半。

## Consequences

- **约定靠注释约束**：`BusComponent` 里"子类不要再写 `onLoad` / `onDestroy`"这句话编译器管不了，写错了会静默丢掉退订。这是本决策的主要长期风险。
- 基类必须 `import 'cc'`，因此**进不了 vitest**：本次的收益记在局部性与杠杆上，可测性的收益全部来自 `renderSignatures.ts`。
- 基类必须标 `@ccclass`（官方文档要求组件类如此，且 `@property` 沿继承链可见）。**`GameRoot` 在场景里连了 6 个 `@property`，改完必须在编辑器里确认连线没断**——这是本次唯一可能静默打坏场景的地方。
- `onEnable` / `onDisable` 仍归子类：只有订阅总线的组件才继承本类，而那两个钩子与订阅无关；`StartView` / `IngredientTray` / `ResultView` / `PrepareTransition` 不订阅总线，继续直接 `extends Component`。
- **新增总线事件时必须在 `BusPayloadMap` 里加一行**，否则 `listen` 认不出它。事件与载荷的对应关系从此只有这一处说明。
- `tests/renderSignatures.test.ts` 新增 12 条：逐字段断言"该影响的必须影响、不该影响的必须不影响"（含一条"每帧都变的倒计时字段不许进签名"，那正是守卫失效的典型错法）。
- 拖拽跟手、动画、切页时序这些仍只能手动验收；本决策不改变那部分。

## 无需重开的既有决策

- ADR-0003 里"过场层的装配、整屏吃触摸与幂等标志"与"判据进 `core`"两条都未触及：本次只换了组件拿到事件的方式，没有搬动任何判据。
- ADR-0005 的落区模块与本次正交：`GameSession` 换了基类，落区的锚点接缝一字未动。
