# 「一份配料」的视觉与图标资源各只有一个所有者

**决定**：两处收口。

1. 新增 `assets/scripts/ui/ingredientGhost.ts`，它是"配料幽灵"（小面板 + 配料图标 + 中文名）的**唯一实现**：拖动时的跟手幽灵与错放时的弹回幽灵共用它，调用方只决定"在哪、叫什么、描边用哪支色"。
2. `assets/scripts/ui/ingredientIcon.ts` 对外只留三个出口——`preloadIngredientIcons()`（交出全部预载任务）、`createIngredientIcon()`（建一个）、`renderIconRow()`（渲染一行）。**帧缓存不再对外可写**：`INGREDIENT_DIR` 与 `loadIngredientFrame` 降为实现内部。

**为什么**：弹回幽灵与跟手幽灵原本各写一份近副本，两份注释还都写着"和拖拽幽灵同款"——靠注释维持的相似，改一处不会牵动另一处。帧缓存那边是一个模块级单例，读写入口都对外暴露，`createIngredientIcon` 还要调用方**多传一个参数**在"预载成功 / 预载失败 / 还没预载"三态里选一个，而两个调用点谁都没传过它：等于一段没人用的接口替缓存的状态机做了一层泄漏。

**连带的收口**：预载任务以前挂在配料盘上（`IngredientTray.preloadIcons`），但 12 张图是配料盘、订单卡、碗与幽灵共用的资源——"由哪一屏发起"只是时序上的偶然。现在组合根直接问图标模块要，于是 `GameRoot` 不再持有配料盘的引用，那段"用 `getComponentInChildren` 递归找配料盘"的兜底与它的长注释一并删除。

## 本次没做的（连同理由，免得下次再被当成遗漏）

- **`renderIconRow` 仍是 5 个参数**（容器 / ids / 图标尺寸 / 间距 / 已放入集合）：把前四个位置参数收成一个选项对象只是换个形式，接口并不更小，读代码时反而要来回对照字段名。
- **图标模块没有单测**：它 `import 'cc'`，进不了 vitest。能测的那部分（一行图标的横排算位）早已抽在 `iconRowLayout.ts` 并已有单测，本模块剩下的全是引擎调用。
- **浮字那三处编排没有收**：得分飘字、连击喊话与"-3 秒"都是 `toLocalPoint → createOutlinedText → setPosition → floatAway`，看着重复，但差异全在数据（字号、颜色、上飘距离、时长、锚点来源）。收成一个助手要 8~9 个参数，接口比重复的那三行还大——按"接口是测试面"的原则不划算，故有意留下。
- **`DropZonePoint` 与 `bus.ts` 的 `DragPointPayload` 没有合并**：两者都是 `{ x, y }`，但没有一个自然归属处能让两边共用（放 `bus.ts` 会让落区模块依赖总线，反之亦然），为两个字段拉一条跨模块依赖不值得。

## Considered Options

- **保留三态参数**：`createIngredientIcon` 内部确实有"缓存未热则异步加载"那条路，但走的是默认参数、不是显式传入；这个参数只在"有人想跳过缓存"时才用得上，而没有人需要。
- **幽灵收一份、但让弹回那份不带图标**：两份幽灵本来就有意长得一样（弹回要让人认出"飞回去的就是刚才那一份"），所以只保留一处不同——描边色（跟手用强调色表示"拿着东西"、弹回用错放红表示"这一份放错了"）。
  > **2026-09-23 被 ADR-0012 部分取代**：跟手那支强调色换成了 `traySlotLabelBase`——幽灵底板已改为与配料盘格子同色的近白，暖金在那块浅底上会糊没。"只保留一处不同——描边色"这条仍然有效。
- **保留 `IngredientTray.preloadIcons` 做一层转发**：那会留下一个只做转发的浅模块，且组合根仍要去找配料盘。

## Consequences

- 错放弹回的那份幽灵**多了配料图标**，名称的**字号 26 → 18、纵向位置 0 → −16**——三处一起看才是"与跟手幽灵同款"。这是本次唯一的可见变化，需要过一眼观感。
- 帧缓存的写时机只有图标模块自己决定；外部想拿图标必须走 `createIngredientIcon`。
- `GameRoot` 少一个字段、少一个装配方法、少一段递归兜底；配料盘少一个 `preloadIcons` 方法。
- 将来若出现第三种幽灵，应当给 `ingredientGhost.ts` 加一个出口，不要另写第二份画法。
