# 落区判定收成一个不 import 引擎的模块，引擎侧从锚点接缝接入

**决定**：拖动的落区判定整块收进 `assets/scripts/game/dropZone.ts`，它**不 import 引擎**——找碗区节点、世界坐标换算、锚点自检这三件要摸引擎的事，经一个 `DropAnchor` 接缝从外面注入（生产实现是 `GameSession` 末尾那个约 35 行的适配器，测试塞假实现）。落区几何（可见框 600×380 + 容差 40）随之从 `config/layout.ts` 搬进这个模块，因为此后只有它一个读。

**接口与实现的分界也一并改了**：模块对外只有两个提问——「这个世界坐标落没落在落区里」与「落区中心在哪」；原来的纯函数 `isWithinDropZone` 从对外接口降为内部实现，"缺锚点怎么办""要不要告警""锚点不是中心怎么办"也都进了实现，不再由调用方各判一次。

**为什么**：加深之前落区的实现分裂在四处——几何在 `config/layout.ts`、两行矩形判定在 `game/dropZone.ts`，而判定真正的编排（找 `BowlArea`、缓存 `UITransform`、缺节点只告警一次、`convertToNodeSpaceAR` 换算、每局复位）住在 `GameSession` 的私有方法里，恰好落在测试面之外；被测的只有喂进局部坐标之后那一步。落区是这块代码里少数带真实分支的判定，它值得被锁住，而锁住的前提是判定与兜底都待在不 import 引擎的一侧。

**为什么容差与可见框要分开表达**：`CONTEXT.md` 原来只写到"看得见的高亮框与落点判定同源"，而"同源"其实只意味着两边都从 `config/layout.ts` 取常量——容差改了，看得见的框不动，没有任何东西会提示这件事。现在两个数出自同一个模块，"看得见的是本体、判得出的是本体 + 容差"这层差别在接口上是显式的；`CONTEXT.md` 的落区词条也在**同一次改动里**改成了这个说法（它的原句不足以表达这件事）。

## Considered Options

- **模块不 import 引擎 + 注入锚点接缝（选中）**：多出一个适配器，换来判定、缺锚点兜底、告警策略全部可被 vitest 覆盖。"一个适配器是假设的接缝，两个才是真接缝"在这里成立：生产是 Cocos 实现、测试是假实现，而"缺锚点""锚点不在中心"这些在引擎里造不出来的情况，只有假实现断言得了。
- **模块直接持有碗区节点**：接口能再小一点（省掉锚点对象），但模块随即 import 引擎，整段逻辑重新变得不可测——与本次加深的目的相反。
- **只把"缺锚点"并进现有纯函数**：改动最小，但编排仍留在 `GameSession`，等于没加深。

## Consequences

- `GameSession` 不再持有碗区变换缓存与缺失告警标志：落区实例**每局新建**（与 `createSession()` 同一风格），"复位"变成"重新构造"，不会漏掉某个字段。
- **缺锚点的语义一字未改**：拖动落点一律判定为落区外（点按路径不经过落区，仍然可用）。
- 锚点不合格（不是 `(0.5, 0.5)`）时**照判 + 告警一次**：判定以节点原点为基准，锚点被挪开会整体平移；不因为一种错配把拖拽整个关掉。
- 告警出口由调用方注入（`warn`），"只告警一次"因此成了可断言的测试项；告警只在**构造期**发，判定路径上一句不喊。
- `tests/dropZone.test.ts` 从 5 条涨到 13 条：原有几何断言（中心、边界、容差内、超容差、正负对称）全部保留，新增缺锚点一律否、缺锚点只告警一次、锚点不合格照判且只告警一次、锚点合格不告警、构造后节点消失不补告警。
- 碗里图例行宽不再从落区宽减一个数算出来，改为自己的常量——它与落区语义无关，捆在一起会一起漂。
- 拖拽跟手、H5 适配、高亮观感这些仍只能手动验收；本决策不改变那部分。

## 无需重开的既有决策

- ADR-0002、ADR-0003 管的是"骨架进场景 vs 运行时装配"与"准备过场"，本决策不触及；`BowlArea` 将来真改成运行时装配，落区模块每局新建的语义也照样成立。
- `README.md` 里"刻意不 import 引擎、因此纳入 vitest 的模块"那份清单，本次只是让 `dropZone` 更彻底地满足这条，不改判定标准。
